- **Expected behavior:** Der volle Expand-Übergang (Klick auf die eingeklappte Island → große Home-Ansicht) und der volle Collapse-Übergang (Home → eingeklappte Island) laufen normalerweise mit einer cleanen, smoothen Spring-Animation (leichter Sprung-/Bounce-Effekt) ab.
- **Actual behavior:** Seit Phase 72.1.1 (Liquid Glass Design Rework) fehlt diese Spring-Animation komplett — harter Schnitt/Sprung ohne jede sichtbare Animation — aber AUSSCHLIESSLICH wenn Material Style "Liquid Glass" aktiv ist. Bei "Gradient" und "Solid Black" funktioniert die Animation weiterhin normal (laut User).
- **Error messages:** Keine — rein visuell, keine Xcode-Console-Warnungen/Logs beobachtet.
- **Timeline:** Seit Einführung von Liquid Glass (Phase 72.1.1, 2026-07-31/08-01). Davor war die Animation immer da.
- **Reproduction:** Klick auf die eingeklappte Island (Collapsed → Home Expand) und wieder zurück (Collapse), mit Material Style = "Liquid Glass" in Settings ausgewählt.

**Explizit NICHT betroffen (per User-Klarstellung nach Rückfrage) — wichtig für Scope:**
- Kleine Wing-zu-Wing-Breiten-Übergänge im eingeklappten Zustand (z.B. Musik-Wing ↔ Helligkeit/Lautstärke-OSD-Wing) — "ist normalerweise auch eine tolle Animation", funktioniert weiterhin.

## Resolution

root_cause: "The native macOS 26+ `.glassEffect()` overlay in `liquidGlassEffectLayer` (the `Color.clear.glassEffect(...)` + stroke ZStack that renders Liquid Glass's actual visible surface) was never tagged into the app's own `matchedGeometryEffect(id: \"island\", in: ns)` animation system that already drives the collapsed<->expanded spring on the outer shape — that system is why Gradient/Solid Black (whose visible content IS that shape's own plain fill) animate perfectly with zero special-casing, while Liquid Glass's content is almost entirely this separate overlay layer (the shape's own fill is near-fully-transparent for `.liquidGlass`). Instead, the overlay relied on Apple's separate glassEffectID/GlassEffectContainer insert-remove-morph system, which never fired correctly for this app's structure: two independently-instantiated per-call-site containers never actually coexist (rounds 1/2), and wrapping real content in one shared container broke rendering at every scope tried (round 3). Round 4's renderer swap (native vs. legacy shader) was also irrelevant, since neither renderer was ever wired into the shape's working matchedGeometryEffect system. Separately, `OSDLevelBar`'s glass Capsule needed its own `GlassEffectContainer` simply to interpolate its `.animation(value: fraction)`-driven frame-width resize — a narrower, unrelated issue (not a morph, just an animated property on a single stable view) that predates this debug session's fix rounds."
fix: "`.matchedGeometryEffect(id: \"island\", in: ns, isSource: false)` added to the native glass ZStack in `liquidGlassEffectLayer` (macOS 26+ branch), tagging it as a passive FOLLOWER in the same id/namespace the outer shape already uses as the (isSource: true, default) LEADER — so the glass content continuously tracks the shape's own already-animating frame every tick, instead of only reading the newly-inserted branch's static resolved size once. `OSDLevelBar`'s glass `Capsule` (~line 5301-5320) wrapped in its own persisting `GlassEffectContainer` so its frame-resize now interpolates too. Rounds 1-4 (glassEffectTransition curve tweak, GlassEffectContainer/glassEffectID removal, switch-arm merge with a shared container, legacy-shader-during-transition swap) were tried and eliminated first — see Eliminated section — before arriving at this matchedGeometryEffect-follower approach."
verification: "Debug build (xcodebuild -project Islet.xcodeproj -scheme Islet -configuration Debug build) succeeded, then confirmed on-device by user (checkpoint round 5, German): 'Ja perfekt alles wieder da.' ('Yes, perfect, everything's back.') All 4 independently-falsifiable checks passed: (a) collapsed<->expanded transition with Liquid Glass shows the spring/bounce again, (b) expanded Home content renders correctly, (c) OSD volume/brightness level-bar fill slides smoothly, (d) OSD wing-to-wing transition still smooth. No further issues reported."
