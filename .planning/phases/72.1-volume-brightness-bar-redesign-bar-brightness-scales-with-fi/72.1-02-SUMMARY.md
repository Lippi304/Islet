# Phase 72.1 Plan 02: OSD Bar Opacity Ramp + Digit-Roll Counter Summary

**OSDLevelBar's fill gained a fraction-driven `.opacity()` ramp with no floor, and the fade-based `.contentTransition(.numericText(value:))` percent counter was fully replaced by a new `DigitRollText` per-digit component that only ever moves, never fades, including across digit-count boundaries (9↔10, 99↔100).**

## Accomplishments
- `OSDLevelBar` fill `Capsule` now dims/brightens with `fraction` via `.opacity(opacityMin + (opacityMax - opacityMin) * Double(fraction))`, `opacityMin`/`opacityMax` wired to Plan 72.1-01's DEBUG nudges, identical formula for both Volume (green) and Brightness (orange) — no hue/lightness interpolation, tint untouched
- New `private struct DigitRollText: View` (placed immediately after `OSDLevelBar`): splits `String(value)` into digits, renders each inside `ZStack { Text(String(digit)).id(digit).transition(.move(edge: .top)) }.frame(width: 8).clipped().transition(.move(edge: .top))` inside an `HStack(spacing: 0)`, animated via `.spring(response: rollResponse, dampingFraction: 0.86)` where `rollResponse = 0.15 + osdRollSpeedNudge`
- Old percent `Text("\(percent)")` with `.contentTransition(.numericText(value:))` and its Quick-task-260729-5pv comment fully removed, replaced by `DigitRollText(value: percent, rollResponse: 0.15 + osdRollSpeedNudge)` in the same `.frame(width: percentTextWidth, alignment: .leading)` slot — `percentTextWidth`/`percentGap` layout untouched
- Both digit character swaps (in-place, e.g. 4→5) and digit-count insert/remove (9→10, 99→100) transition via `.move` only — the outer per-digit wrapper's own `.transition(.move(edge: .top))` after `.clipped()` prevents SwiftUI's default opacity-fade fallback on insert/remove
