# Phase 72 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase restyles and extends the ALREADY-shipped two-column `calendarContent` (Phase 28) inside the existing `blobShape`/`islandFill` gradient chrome (Phase 25) at the existing `calendarWidth` (472pt × `resolvedWidthScale`). It does not redefine the shell material, corner radii, or spring constants. Four things change: (1) `dayListColumn` becomes a scrollable, whole-month, day-grouped agenda instead of a single-selected-day list, (2) badge/weekday-header/chevron/font-size visual language is brought into 1:1 alignment with `reference-macos-calendar-widgets.png`, (3) event rows gain hover-reveal edit/delete + a title tooltip, (4) `CalendarService` gains update/delete. All typography/color/spacing values below reuse this file's own established `NotchPillView.swift` conventions (verified by direct code read) plus the new red accent introduced specifically to match the reference screenshot — no parallel design language is introduced.

## Spacing Scale

Reuses `NotchPillView.swift`'s existing in-chrome numbers verbatim — no new scale introduced.

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| xs | 4px | Weekday-letter-to-grid vertical gap; day-group header top gap |
| sm | 8px | `monthGridColumn` internal `VStack` spacing (unchanged); agenda row internal spacing |
| md | 16px | `calendarContent` horizontal content padding (unchanged) |
| lg | 24px | Not directly used this phase (reserved token, unchanged) |
| xl+ | — | Not used this phase |

Exceptions:
- Month-grid day cell grows from 18×18pt to **22×22pt** (D-11 font-size bump forces a matching cell-size bump so the larger number doesn't collide with the "has-events" dot or the cell edge) — stays below the 44pt HIG tap-target minimum, same accepted precedent as Phase 28's original 28pt cells (dense glanceable data-grid, not a primary action).
- Calendar-cell gap stays 2px (unchanged) — only the cell itself grows, so the grid's total footprint grows from ~138pt to ~158pt width; `calendarWidth` (472pt) already has headroom, no further island-width bump needed for this alone.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Existing Phase 25 black-to-transparent gradient shell (`islandFill`) | Whole island background — unchanged, out of scope |
| Secondary (30%) | `Color.white.opacity(0.06)` rounded cards (8pt radius) | Event rows (unchanged), agenda list background implicitly transparent over shell |
| Accent (10%, NEW this phase) | `Color.red` (system semantic red — Open Question 1's recommendation: use semantic `.red`, only sample exact RGB from the PNG if on-device comparison shows a visible mismatch) | Reserved for exactly 3 elements, matching the reference screenshot: (1) month/year header label text, (2) today's filled day badge, (3) selected (non-today) day's outline ring. **Nowhere else.** Per-event color dots (`EventInput.colorRed/Green/Blue`, EventKit-sourced) are a separate, pre-existing data-driven color channel — never overridden by this red accent. |
| Destructive | `Color.white.opacity(0.7)` (NOT red) | Hover-reveal delete (trash) icon on event rows — deliberately reuses this codebase's existing neutral-white trash-icon convention (Shelf clear-all icon, `NotchPillView.swift:2999`) rather than introducing red-for-destructive, since D-08 already establishes "no confirm dialog" (low-stakes delete) and this file has zero existing red-for-destructive precedent to break from |

Accent reserved for: **month/year header text, today's filled circle badge, selected-day's outline ring — nothing else.** Do not tint chevrons, weekday letters, event-row text, or the has-events dot red.

## Layout Contract

### Weekday header row (NEW — Pitfall 2 confirmed this does not exist in the codebase today)

| Property | Value | Source |
|----------|-------|--------|
| Position | New row inserted into `monthGridColumn`'s `VStack`, between the month/year header and the `LazyVGrid` | New |
| Columns | 7, locale-aware via `Calendar.current.veryShortWeekdaySymbols` rotated by `calendar.firstWeekday` (Research Pattern 3) — NOT a hardcoded `["M","D","M","D","F","S","S"]` array | New, Foundation `Calendar` API |
| Alignment | Must share the exact same `GridItem(.fixed(calendarCellSize), spacing: calendarCellGap)` column definition as the day-number `LazyVGrid` below it, or letters will not line up with date columns | Pitfall 2 warning |
| Font/color | 10px semibold rounded, `.secondary` foregroundStyle (not full white) | New |

### Month header chevrons (D-10 — move closer together)

| Property | Value | Source |
|----------|-------|--------|
| Current | `HStack { chevronLeft; Spacer(); monthLabel; Spacer(); chevronRight }` — chevrons pushed to the full row width's edges | Existing code, ~line 1622 |
| New | Replace both `Spacer()` with a fixed `8pt` gap on each side of the centered month label (`HStack(spacing: 8) { chevronLeft; monthLabel; chevronRight }` wrapped in an outer `HStack` that centers this group) — chevrons hug the label instead of sitting at the grid's outer edges | D-10 |

### Month grid day badge (D-03 — swap, Pitfall 3 warning)

| State | Visual | Source |
|-------|--------|--------|
| `isToday` (regardless of selection) | Solid filled circle, `Color.red` fill — wins visually over selection per the reference PNG (today's cell shows no additional ring even when also selected) | D-03, Pitfall 3 |
| `isSelected && !isToday` | Thin red outline ring, `Color.red` stroke, `lineWidth: 1.5`, no fill | D-03 (German: "dünner roter Ring") |
| Neither | No badge — plain number | Unchanged |
| Has-events dot (D-04 resolution) | **Keep, unchanged** — small `2×2pt` white dot at `opacity(0.6)`, offset below the number. Resolved per RESEARCH.md's recommendation: the reference PNG's bare month widget shows no dots because Apple's real widget relies on the agenda to convey "has events," but removing a working, already-shipped affordance isn't asked for by any locked decision — keep it as-is. | D-04, Claude's discretion — resolved KEEP |
| Selected-day font weight | Semibold when `isSelected` OR `isToday` (unchanged logic, just larger size per Typography) | Existing, size bumped only |

Implementation note for Pitfall 3: write as one pair — `isToday` → filled red; `isSelected && !isToday` → red ring. A diff touching only one of the two conditions is wrong.

### Agenda list — day-grouped, whole-month, scrollable (D-01/D-02, CALVIEW-08)

| Property | Value | Source |
|----------|-------|--------|
| Scope | Every day in `calendarViewState.visibleMonth` that has ≥1 event — NOT a rolling window from today, NOT filtered to the selected day alone | D-01 |
| Grouping | `eventsByDay(events:calendar:)` pure function (`CalendarGlance.swift`), grouped by `startOfDay(for:)` `Date` key (never a formatted `String` key — Pitfall 5) | RESEARCH.md Pattern 1 |
| Day-group header copy | `"WEDNESDAY, 15 JUL"` format — `Text(day, format: .dateTime.weekday(.wide).day().month(.abbreviated))`, `.textCase(.uppercase)`, `.secondary` | Droppy convention (still valid per CONTEXT.md D-05), 11px semibold |
| Scroll container | `ScrollViewReader` wraps the existing `ScrollView(.vertical)`; each day-group header carries `.id(day)` (the grouping `Date`, not a string) | RESEARCH.md Pattern 2 |
| Scroll-to-day trigger | `.onChange(of: calendarViewState.selectedDay)` on the reader's content → `proxy.scrollTo(startOfDay(selectedDay), anchor: .top)`, wrapped in `withAnimation` | D-02 |
| Empty state | Unchanged `calendarEmptyState` copy, but now triggers only when the WHOLE visible month has zero events (not just the selected day) | Scope change from single-day to whole-month empty check |
| Event row (extended) | Existing rounded-card row (`Color.white.opacity(0.06)`, 8pt corner radius, color-dot + title + time) PLUS: hover-reveal trash icon (trailing edge), `.help()` tooltip showing the full untruncated title, tap-to-open edit popover | Extends Phase 28/46 row styling |

### Event row hover affordances (D-07/D-08/D-12, Pitfall 4)

| Affordance | Trigger | Visual | Behavior |
|------------|---------|--------|----------|
| Full-title tooltip (D-12) | System `.help()` modifier on the row (or the truncated `Text`) — standard macOS hover tooltip, no custom view | Native tooltip bubble showing the FULL untruncated `event.title` | Read-only; must never crash/interpolate the untrusted `EKEvent.title` into anything but a plain `Text`/native tooltip (Security Domain V5) |
| Edit (D-07) | Tap anywhere on the row (excluding the trash icon's own hit area) | No visual change on tap itself — opens a popover | Opens a NEW sibling popover reusing `QuickAddPopover`'s exact visual chrome (240pt width, 12pt padding, segmented-picker-free since edit only touches Event fields, pre-filled `title`/`startTime`/`endTime` from the tapped `EventInput`), submit button reads **"Save"** (not "Add Event" — this is an edit, not a create) |
| Delete (D-08) | Hover reveals a trailing trash icon at `Color.white.opacity(0.7)`, `12-14px`, hidden (`opacity(0)`) when not hovering — per-row **local** `@State private var isHovering` (Pitfall 4: do NOT use controller-owned `presentationState.hoveredQuickActionButtonIndex` for this unbounded, refetch-changing list) | Icon fades in/out on hover, matches `TransportButton`'s exact local-hover pattern (`NotchPillView.swift:4552`) | One tap = immediate delete, **no confirm dialog** (D-08) — calls `onEventDelete(event.id)` directly |

### Island width

No change to `calendarWidth` (472pt) required by this phase's own layout math (grid grows ~20pt, already has headroom within the existing 472pt box); if on-device UAT finds visible crowding after the cell/font bumps land, treat as a gap-closure constant tweak, not new scaling infrastructure (reuses `resolvedWidthScale`, per RESEARCH.md).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (create) | **"+ Add"** (trigger, unchanged) → popover submit: **"Add Event"** / **"Add Reminder"** (swaps with type picker, unchanged) |

| Full-title tooltip | Native OS tooltip showing the untruncated `event.title` verbatim — no added copy/wrapper text |
