<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Free-form user text input → vault `.md` file | Intentionally unvalidated/unsanitized — the text becomes literal Markdown in the user's own vault, that IS the feature (RESEARCH.md V5 assessment) |
| AppDelegate → user-chosen folder path (read from UserDefaults) | The path itself is never user-typed (only ever comes from Plan 64-03's NSOpenPanel), so no path-injection surface — but the folder's continued existence/writability is not guaranteed between picks |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-64-02 | Repudiation | `handleQuickNoteSubmit` | mitigate | D-12's locked guard — `QuickNotesStore.append` only runs inside `QuickNotesVaultWriter.append`'s success path; a failed write never appears as a saved note, the typed text remains in the input untouched |
| T-64-03 | Tampering | `openQuickNotesPopover` | mitigate | D-11 — `QuickNotesVaultWriter.isValidVaultFolder` re-checked fresh on every popover open (not cached), so a folder deleted/moved/recreated between opens is caught before the user starts typing into a broken target |
| T-64-08 | Denial of Service | `NSPopover` keyboard focus (Pitfall 10) | accept | Genuinely unverified AppKit mechanic — flagged explicitly for the Plan 64-05 on-device spike rather than silently assumed; if focus never lands reliably that plan's checkpoint surfaces it as a real blocker, not a silent failure |

</threat_model>
