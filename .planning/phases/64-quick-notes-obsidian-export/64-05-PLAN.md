    1. Build and launch a Debug build of Islet. In Settings → Quick Notes card, click the options button and choose a real folder (pick one under `~/Documents` specifically, to exercise the TCC-protected-folder path — Assumption A4).
    2. Click the menu-bar status icon → "New Note…". WITHOUT clicking anywhere first, start typing immediately. Confirm the characters land in the text field (Pitfall 10 / Assumption A1). If focus does not land without an extra click, this is a real finding — report it exactly as observed, do not treat it as a minor issue.
    3. Type a multi-line note (press plain Return once to insert a newline, then more text), then press Cmd+Return. Confirm: (a) the note was submitted while the TextEditor still had focus (Assumption A2), (b) the popover stayed open, (c) the input field cleared, (d) the new note appears at the top of the recent-notes list with a correct `HH:mm` timestamp.
    4. Confirm the macOS "would like to access files in your Documents folder" TCC prompt appeared on that first write (or note if it did not — Assumption A4 flags this as genuinely uncertain). Grant it. Quit and relaunch Islet, submit a second note to the same folder, confirm NO repeat TCC prompt.
    5. Open the vault folder in Finder (Obsidian.app must be CLOSED for this step — NOTES-02's own success criterion). Open `Islet Notes.md` in a plain text editor. Confirm the exact D-05 format: a `## YYYY-MM-DD` heading, `- HH:mm <text>` bullets, and any multi-line note's continuation lines indented by exactly 2 spaces.
    6. Submit one more note, then IMMEDIATELY force-quit Islet (Activity Monitor or `kill -9`) while the write is in flight if possible, or at minimum immediately after a submit. Relaunch Islet, reopen `Islet Notes.md`, confirm all PRIOR content is intact and uncorrupted (Pitfall 7 — the highest-stakes check in this phase).
    7. Hover a row in the recent-notes list, confirm the red trash icon appears at the trailing edge; click it, confirm that ONE entry disappears from the list immediately with no confirmation dialog, then reopen `Islet Notes.md` and confirm the deleted note's line is STILL PRESENT in the vault file (D-17 — local delete never touches the vault).
    8. In Settings, clear/change the vault folder to a non-existent path (or temporarily rename the chosen folder in Finder), then reopen "New Note…" — confirm the popover shows the "Vault folder not set" empty state with input disabled (D-11, re-checked fresh on open) rather than silently accepting a note that can't be saved.
    9. Restore a valid vault folder, submit a note pointed at a location where the write will fail (e.g. a path with revoked permissions, if reproducible) — confirm the error banner reads exactly "Couldn't save — check your vault folder in Settings.", the typed text remains in the field, and the failed note does NOT appear in the recent-notes list (D-12).
  </how-to-verify>
