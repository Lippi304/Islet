<objective>
Fix three UAT-reported regressions in the already-shipped Quick Notes popover/menu (Plan 64-04's own on-device UAT, `64-UAT.md` tests 2, 7, 8) plus one minor menu-ordering request — all four are bugs against this phase's own locked spec, not scope changes.

Root cause for the two focus-related bugs (UAT tests 2 and 8) is the SAME line of code: `AppDelegate.openQuickNotesPopover()` unconditionally calls `window?.makeFirstResponder(quickNotesPopover.contentViewController?.view)` on every open. This targets the outer `NSHostingController` content view (not the actual `NSTextView` backing SwiftUI's `TextEditor`), which is why typing without a click fails, and calling it even when every control is `.disabled(true)` (the vault-not-configured empty state) is what leaves the popover's `.transient` outside-click dismissal unable to complete. The scrollbar bug (UAT test 7's hit-target half) and the menu-order bug (UAT test 1's screenshot) are independent, smaller fixes bundled into this plan because they touch the same two files.

Purpose: restore the popover/menu to its originally-specified behavior (D-01/D-03/D-11/D-17's hit-target intent) before layering the two approved scope changes (vault-delete, multi-file) on top in Plans 64-07/64-08.
Output: `QuickNotesPopoverView.swift` and `AppDelegate.swift` updated; all four fixes confirmed on-device via this plan's own checkpoint.
