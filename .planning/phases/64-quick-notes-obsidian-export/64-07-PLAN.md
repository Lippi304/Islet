  <action>
    Add to `QuickNotesVaultWriter` (do not modify `append`/`readTail`): `enum VaultDeleteResult: Equatable { case removed, notFound }` and `static func removeEntry(matching note: QuickNote, from fileURL: URL) throws -> VaultDeleteResult`.

    Algorithm for `removeEntry`: if `FileManager.default.fileExists(atPath: fileURL.path)` is false, return `.notFound` immediately (no throw, no file created). Otherwise read the WHOLE file via `let data = try Data(contentsOf: fileURL)` (this throws on a genuine I/O/permission failure — let it propagate) and decode it with `String(data: data, encoding: .utf8)`; if decoding fails, throw a small local error type (e.g. a `struct DecodeError: Error {}`) rather than silently proceeding — a non-UTF8 vault file is a real failure, not a "line not found" case. Build the exact match string via `QuickNotesFormatter.formatEntry(text: note.text, at: note.timestamp)` (identical to what `append` originally wrote) and locate it with `content.range(of: entryBlock)`; if `nil`, return `.notFound`. If found, `removeSubrange` that exact range from a mutable copy of the content, then write the result to a hidden temp file in the SAME directory as the target (`fileURL.deletingLastPathComponent().appendingPathComponent(".\(fileURL.lastPathComponent).tmp-\(UUID().uuidString)")`) via `try updated.write(to: tempURL, atomically: true, encoding: .utf8)`, then atomically swap it into place with `_ = try FileManager.default.replaceItemAt(fileURL, withItemAt: tempURL)` and return `.removed`.

    Document directly above `removeEntry` (as a comment) that this is the ONE deliberate, scoped exception to D-07's append-only rule in this file: it is justified because (a) it only runs on an explicit, rare, single-row user delete, never on the hot append path, and (b) `FileManager.replaceItemAt` performs an atomic rename, giving the same "safe save while another process (Obsidian) may have the file open" guarantee ordinary text editors rely on — never a truncating in-place rewrite.

    Add `static func listMarkdownFiles(inFolder path: String) -> [String]`: `let entries = (try? FileManager.default.contentsOfDirectory(atPath: path)) ?? []; return entries.filter { $0.hasSuffix(".md") }.sorted()`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Islet <-> external Obsidian vault file | The vault `.md` file is owned by the user and may be open/edited by Obsidian.app concurrently. removeEntry is the first Islet code path that rewrites (not just appends to) this file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-64-12 | Tampering | QuickNotesVaultWriter.removeEntry — full-file read + rewrite | mitigate | Atomic temp-file-in-same-directory + `FileManager.replaceItemAt` (kernel-level rename), never a truncating in-place write; scoped to the explicit, rare delete action only — append/readTail (the hot path) are untouched |
| T-64-13 | Repudiation-adjacent (silent data loss if the wrong line were removed) | QuickNotesVaultWriter.removeEntry line-matching | mitigate | Match by the exact formatted entry string produced by the same `QuickNotesFormatter.formatEntry` used at write time; a non-match returns `.notFound` (safe no-op) rather than guessing or removing an approximate line |
| T-64-14 | Tampering (concurrent Obsidian.app write during the delete-rewrite window) | External vault file, real disk, single local user | accept | Same acceptance rationale as RESEARCH.md Pitfall 11: single-process, single-writer app; `replaceItemAt`'s atomic rename gives the same safety guarantee ordinary editors' "safe save" relies on for a file another process may have open |

</threat_model>
