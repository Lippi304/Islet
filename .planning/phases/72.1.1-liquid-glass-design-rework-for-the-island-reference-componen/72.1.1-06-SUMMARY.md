**OSD volume/brightness bars now render real macOS 26+ Liquid Glass on their fixed-hue fill via `Glass.clear.tint(tint)` (not `.regular`, which was found on-device to wash out the green/orange color), closing out Phase 72.1.1 with a confirmed 5-call-site structural invariant, a clean 588-test suite (9 pre-existing failures, zero new), and full UI-SPEC On-Device UAT Gate approval.**

## Accomplishments

- `OSDLevelBar`'s filled `Capsule` now renders via a guarded `.glassEffect()` on macOS 26+ (`Capsule().fill(Color.clear).glassEffect(.clear.tint(tint), in: Capsule())`), unchanged `.fill(tint)` legacy fallback below that — `tint` (green for volume, orange for brightness, Phase 39 D-02 locked) passed straight through in both branches.
- Re-confirmed `debugOSDOpacity` is genuinely absent (0 matches) before implementing — Pitfall 4's "opacity ramp was reverted" premise still holds, D-07 stays a simple single-layer glass addition with no ramp-coordination logic.
- Phase-closing structural invariant confirmed: `grep -c "\.overlay(liquidGlassEffectLayer(shape:"` returns exactly **5** — no 6th shell call site was added across Plans 72.1.1-01 through 06.
- Phase-closing full XCTest suite run: 588 tests, 9 failures — all 9 match the pre-existing documented baseline (4x `LicenseStateTests`, 3x `SettingsViewTests` card-count drift, 2x `CalendarGlanceTests` time-of-day-dependent flakes, per `72-calendar-redesign-native-calendar-clone/deferred-items.md`). **Zero new failures.**
- On-device UAT gap-closure: the first implementation used `Glass.regular.tint(tint)` (matching every other D-06 element's convention in Plans 04-05); the user reported on-device that the bars had lost their distinctive green/orange color entirely. Root-caused to the same `Glass.regular` oversaturation/desaturation behavior Plan 03 already isolated on the island shell — fixed by switching to `Glass.clear`, which (per Plan 03's SDK-confirmed finding) is the only lever available since `Glass`'s public API has no independent saturation control. Re-verified on-device and approved.

### Auto-fixed Issues

**1. [Rule 1 - Bug] `Glass.regular` washed out OSDLevelBar's green/orange semantic hue**
- **Found during:** Task 3 checkpoint (on-device UAT, item 14)
- **Issue:** The plan's specified implementation (`.glassEffect(.regular.tint(tint), in: Capsule())`, matching Plans 04-05's `.regular` convention) desaturated/washed out the bar's green (volume) / orange (brightness) color on-device, contradicting D-07's explicit "green/orange hue unchanged" requirement. - **Fix:** Switched to `Glass.clear.tint(tint)` — matching the island shell's own choice (`:836`, Plan 03), made there for the identical reason: `Glass`'s public SDK API has no independent saturation/vibrancy control, so `.clear` vs `.regular` is the only lever, and `.clear` reproduces tint color accurately while `.regular` does not.
- **Files modified:** `Islet/Notch/NotchPillView.swift`
