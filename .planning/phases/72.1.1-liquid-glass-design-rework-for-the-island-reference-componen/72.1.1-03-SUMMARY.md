# Phase 72.1.1 Plan 03: Full-Surface Liquid Glass Coverage Summary

**Scaled Liquid Glass from a thin rim to the full island surface on both rendering paths, then closed 3 real on-device regressions the surface-area change exposed: a hover-to-expand hang tied specifically to the literal `Color.clear` value, a collapse↔expand animation that silently degraded into a cross-fade, and an oversaturated color read fixed by switching to Apple's `Glass.clear` style.**

## Performance

- **Duration:** multi-session (13 checkpoint rounds — see Deviations)
- **Completed:** 2026-07-31
- **Tasks:** 3 (2 auto, 1 checkpoint:human-verify — the checkpoint itself expanded into an extensive on-device gap-closure investigation)
- **Files modified:** 2

## Accomplishments

- Native (macOS 26+) `liquidGlassEffectLayer` now applies `.glassEffect()` to the bare full island `shape` instead of the old `LiquidGlassRimRingShape` rim ring (D-01), with a tunable tint (`glassTintNudge`) and a tunable specular top-highlight stroke (`glassGlossNudge`).
- Legacy (<macOS 26) `legacyLiquidGlassEffectLayer` retuned (`LiquidGlassParameters.collapsed`/`.expanded`: wider rim band, reduced edge/center opacity contrast) for the same full-coverage intent, independently tunable via 3 legacy nudge axes wired through a local `tunedParameters` value.
- Found and fixed the actual root cause of "always just black, never real glass" (the D-01 gap the checkpoint surfaced): `islandFill`'s `.liquidGlass` case was painting a near-opaque `gradientMaterial` fill *underneath* the glass overlay, in the same window, leaving `.glassEffect()` nothing real to refract despite the NSPanel itself being genuinely `isOpaque = false`.
- Isolated a genuine platform gotcha through careful on-device bisection: `Color.clear` as the literal fill value hangs hover-to-expand entirely (reproduced twice), while `Color.black.opacity(0.0001)` — visually indistinguishable from true transparency — does not. Confirmed this is not a gradual transparency-amount effect (0.01 and 0.0001 both safe, no instability gradient toward zero); it isolates specifically to the exact `Color.clear` constant/type.
- Found and fixed a second real regression the full-surface change exposed: the collapse↔expand size-morph animation had silently degraded into a plain cross-fade, because the native glass overlay carried its own explicit `.frame(width: size.width, height: size.height)` — a static, non-animated target size — instead of inheriting the parent shape's live `matchedGeometryEffect`-driven frame via `.overlay()`'s default sizing.
- Diagnosed a perceived color/saturation boost as inherent to Apple's system Liquid Glass material (confirmed via the real SDK's `SwiftUICore.swiftinterface`: `Glass`'s public API has no saturation/vibrancy control at all) and resolved it the only way the API allows — switching from `.regular` to `.clear` as the base Glass style — user-approved on-device.
- Re-confirmed, at the final shipped combination, that Plan 72.1.1-01's D-04 transition-continuity fix still holds, the rim/base animation-curve desync flagged in that plan's own known-issues is resolved (structural byproduct of merging rim+base into one glass surface, as anticipated), no cursor/pointer-follow reactivity exists (D-05), and text/icon legibility holds (D-02).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `islandFill`'s opaque base fill blocked all real Liquid Glass backdrop-sampling**
- **Found during:** Task 3 checkpoint (initial on-device UAT)
- **Issue:** `.liquidGlass` mode painted a near-opaque `gradientMaterial` fill on the same shape the `.glassEffect()` overlay sits above, in the same genuinely-transparent NSPanel — `.glassEffect()` had nothing real to refract regardless of tint/gloss tuning.
- **Fix:** `islandFill`'s `.liquidGlass` case returns a fill that doesn't paint an opaque backdrop.
- **Files modified:** `Islet/Notch/NotchPillView.swift`
- **Verification:** On-device, multiple rounds (see below).
- **Committed in:** `96b8a3b`, iterated through `243db3d`, `72b050f`, `2977d3b`, `eab8a24`, `b36b71f`, `5295f7e`

**2. [Rule 1 - Bug] Literal `Color.clear` hangs hover-to-expand entirely**
- **Found during:** Task 3 checkpoint gap-closure, round 1 (`Color.clear`) and round 4 (retest)
- **Issue:** Setting `islandFill`'s `.liquidGlass` case to the literal `Color.clear` constant caused hover-to-expand to stop working completely on-device, reproduced independently after a full app restart and again on a deliberate retest — while every nonzero alpha tested (0.05, 0.01, 0.0001) worked with no hang and no visible gradient of instability. Ruled out a SwiftUI hit-testing regression by code inspection: hover/click-through in `NotchWindowController` is driven entirely by a global `NSEvent` monitor + geometric rect math, never touching this view's rendered content.
- **Fix:** Settled on `Color.black.opacity(0.0001)` — technically nonzero, visually identical to true transparency, confirmed safe.
- **Files modified:** `Islet/Notch/NotchPillView.swift`
- **Verification:** On-device, 5 bisection rounds.
- **Committed in:** `243db3d` (revert), `72b050f`, `2977d3b`, `eab8a24` (retest+reconfirm), `b36b71f`, `5295f7e` (lock-in)

**3. [Rule 1 - Bug] Collapse↔expand size-morph animation silently became a cross-fade**
- **Found during:** Task 3 checkpoint gap-closure, after round 3 (opacity stepping) made the glass layer's own behavior visually dominant enough to notice
- **Issue:** `liquidGlassEffectLayer`'s native-branch `Color.clear` glass base carried an explicit `.frame(width: size.width, height: size.height)`. `size` is a plain, non-animated `CGSize` recomputed per call site — never routed through `matchedGeometryEffect`. The fixed frame snapped the glass layer straight to each call site's static target size every render instead of inheriting `.overlay()`'s default sizing (which tracks the parent shape's live, matchedGeometryEffect-animated frame at each tick). This defect existed since Plan 72.1.1-01 too, just invisible while the glass region was a thin rim.
- **Fix:** Removed the explicit `.frame(...)` call; the glass base now inherits `.overlay()`'s default sizing, matching the sibling specular highlight stroke's existing (frame-less) convention.
- **Files modified:** `Islet/Notch/NotchPillView.swift`
- **Verification:** On-device — user confirmed "alles approved" at the final combination (morph animation restored, D-04 flat-black fix still holds).
- **Committed in:** `4055ad7`

## Known Issues

**Legacy (<macOS 26) path: black-rectangle rendering artifact around expanded-view content (unresolved, deferred)**
- **Symptom:** When the `#available(macOS 26.0, *)` branch is forced to always take the legacy path (temporary local test only, never committed), the now-playing/expanded content card renders as a sharp-edged, fully opaque black rectangle floating inside an otherwise-correctly-frosted outer panel — on every expanded view (Home/Calendar/Weather/Tray), not just Now Playing.
- **Confirmed:** Does NOT occur on the native path (macOS 26+, what actually runs on this hardware) — only appears when the legacy branch is forced.
- **Investigation:** No hardcoded background found in `mediaContent` or the shared `blobShape` skeleton (both were read in full — neither has its own `Color.black`/opaque fill). Leading hypothesis: a Metal shader/Core Animation compositing artifact in `legacyLiquidGlassEffectLayer`'s `.colorEffect`/`.distortionEffect`/`.blendMode(.screen)` chain interacting with the near-zero `islandFill` (`0.0001`) at the larger expanded size — this exact combination (near-zero base fill + Task 2's retuned wider-band legacy parameters) was never tested until this round, since the legacy branch hadn't executed since before this plan's opacity changes.
- **Not resolved further:** Root-causing a Metal/compositing artifact needs an actual GPU frame capture (Xcode's on-device debugger), which can't be driven from this environment. Deferred by explicit user decision ("mach so weiter wie du denkst" — do what you think is right) rather than continuing to guess-edit shader/compositing code blind.
- **Scope note:** This is squarely Plan 72.1.1-03's own scope (the legacy fallback this plan's Task 2 retuned, exposed by this plan's own Task 3 `islandFill` fix) — not a later-wave (D-06 Tier 1/2) issue. Flagged for a future round if/when the legacy (<macOS 26) path becomes a real concern again (current deployment target support means the native path is what actually ships/runs today).
