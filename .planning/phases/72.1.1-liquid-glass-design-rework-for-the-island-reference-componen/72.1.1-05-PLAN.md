<objective>
Extend Liquid Glass to the three D-06 "Tier 2" content-surface elements — Calendar event cards (`EventRow`), the Weather widget (`weatherFullContent`), and Tray file tiles (`ShelfItemView`) — per CONTEXT.md D-06 and UI-SPEC's Tier 2 contract (readability-first, lower intensity than Tier 1 controls, since Apple's own Liquid Glass guidance warns against glassifying dense content surfaces — RESEARCH.md Pitfall 3).

`EventRow` already has a card background to convert; `weatherFullContent` and `ShelfItemView` currently have NO background box at all and need one added (a small, necessary structural addition per UI-SPEC's Layout/Spacing Contract "Exception" — not a redesign). All three reuse the exact same `RoundedRectangle(cornerRadius: 8, style: .continuous)` + `Color.white.opacity(0.06)` convention, for visual consistency with `EventRow`'s and `quickActionButton`'s existing look — and all three wrap their new `.glassEffect(...)` call in the same `if #available(macOS 26.0, *) { ... } else { ... }` guard already established in this file (`NotchPillView.swift:750`, `:4561`), since the project's deployment target is macOS 15.0 and `.glassEffect(_:in:isEnabled:)` is `@available(macOS 26.0, *)`. The `else` branch is the plain `.fill(Color.white.opacity(0.06))` — for `EventRow` that's its exact pre-existing fill; for Weather/Tray (which have no background today) it's the same plain fill the glass branch's tint value is based on.

Purpose: Complete D-06's content-surface coverage while treating legibility as the primary constraint (D-02) — this is the highest-legibility-risk group in the phase (RESEARCH.md Pitfall 3), so verification is on-device per element, not assumed from the controls-tier result. Every new glass call also compiles cleanly at the project's actual deployment target.
Output: Calendar cards, Weather widget, and Tray tiles all show glass on macOS 26+ (plain fill unchanged below that); on-device UAT confirms text/icon/badge legibility holds on all three.
</objective>
