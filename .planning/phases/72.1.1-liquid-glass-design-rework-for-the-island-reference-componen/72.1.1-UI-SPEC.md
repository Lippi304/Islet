# Phase 72.1.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** Islet is a native macOS SwiftUI/AppKit app (no React/Next.js/Vite, no npm, no `components.json`/`tailwind.config.*` anywhere in the repo). The shadcn initialization gate does not apply — this contract is expressed in SwiftUI-native terms (points, `ShapeStyle`, `.glassEffect()`, `.distortionEffect()` Metal shader, `@AppStorage`) instead of web tokens, following the exact convention already established in `35-UI-SPEC.md` and `72.1-UI-SPEC.md`.

**Scope note:** This is a REWORK, not a from-scratch design. It reverts/extends an already-shipped Liquid Glass implementation (Phase 35) from a thin rim (`LiquidGlassRimRingShape`) back to full-surface coverage, fixes a known transition-flicker bug (D-04), and extends glass treatment to 6 separate inner-element render locations (D-06). The `21st.dev/r/suraj-xd/liquid-glass` reference is a **visual/behavioral reference only** (macOS-Dock-icon-style glass) — it is never installed, fetched as a package, or run; the actual technique class it points at is already ported natively in this codebase (`LiquidGlassShader.metal`, native `.glassEffect()`).

## Island Shell Material Contract (D-01, D-02, D-03) — the primary target

**Structural constraint:** applies as a modifier on the SAME shape node that already carries `.matchedGeometryEffect(id: "island", in: ns)` at all 4 existing shell call sites (`NotchPillView.swift:1378, 2937, 3219, 3401` approx.) — never a new sibling/wrapper view. This project already broke `matchedGeometryEffect` continuity once doing exactly this class of change (WR-02) — do not repeat it.

| Property | Value |
|----------|-------|
| Coverage | Full island `shape` (collapsed pill, expanded island, all activity wings) — **not** `LiquidGlassRimRingShape`. Reverts the native `.glassEffect(_:in:)` call's shape argument from the rim ring back to the base `shape`, the pre-D-20a code path (`35-CONTEXT.md`) that is known to compile and render |
| Gradient direction (base layer) | UNCHANGED — top-black → bottom-transparent (`gradientMaterial`, Phase 25/35 D-02). The glass layer composites ON TOP of this gradient, never replaces its stops or direction |
| Glass tint starting point | `Glass.regular.tint(Color.black.opacity(0.7))` — the D-20-era starting value (pre-D-20a). Not final: readable-vs-glossy tradeoff must be tuned on-device (see DEBUG Tuner Contract below); do not hardcode a different literal without going through the tuner |
| "Glossier" execution | Claude's/executor's discretion (specular highlight strength, blur-clarity, rim-light stroke brightness, or a combination) — pick whichever reads best on-device (CONTEXT.md explicit discretion). Whatever is chosen must be tunable via the DEBUG menu, not a baked guess |
| Readability precedence (D-02) | If full-surface glass coverage degrades text/icon legibility (track titles, calendar text, Settings-adjacent labels, transport controls) anywhere, DIAL BACK glass intensity — never the reverse. This is a hard, non-negotiable precedence carried from Phase 35's D-15 |
| Foreground content | Album art, equalizer bars, text, icons, buttons stay crisp/undistorted — the glass/distortion applies to the fill layer only (unchanged constraint from Phase 35 D-03) |

**Legacy shader fallback (`<macOS 26`, deployment target confirmed 15.0 — this path is user-facing, not theoretical):**

| Property | Value |
|----------|-------|
| Mechanism | `legacyLiquidGlassEffectLayer` / `LiquidGlassShader.metal` — reuse 100% of the existing shader functions (`liquidGlassEdgeOpacity`, `liquidGlassDistortion`); pure parameter retuning, no new shader code |
| Direction of retune | Widen `LiquidGlassParameters.collapsed`/`.expanded`'s `borderWidth`/`blurWidth` (the rim-band width) and reduce `edgeOpacity`/`centerOpacity` contrast so the dark center no longer dominates — this fallback must independently satisfy D-01 (full coverage) and D-03 (legibility), not just visually approximate the native path |
| Verification | Force the `else` branch locally on the macOS 26 dev machine (Swift compiles all `#available` branches unconditionally — confirmed existing comment at `NotchPillView.swift:743-744`) since a genuinely older test machine may not be available |

## State Coverage Contract (D-03, D-04, D-05)

| State | Requirement |
|-------|-------------|
| Collapsed pill (idle) | Glass visibly present, full-shape coverage |
| Mid collapse↔expand animation | Glass renders CONTINUOUSLY through the morph — no flat-black/flat-color frame at any point. This is the D-04 bug fix target |
| Compact/small expanded state | Glass visibly present, same as full expanded |
| Full expanded island | Glass visibly present, full-shape coverage |
| Tab switches (view switcher) | Glass renders continuously — no drop-to-black during the switch, same class of fix as the collapse↔expand case |

**Transition-continuity mechanism (D-04):**

| Property | Value |
|----------|-------|
| Mechanism | `GlassEffectContainer` + a stable, SHARED `.glassEffectID("islandGlass", in: glassNS)` — a dedicated `@Namespace` separate from the existing `matchedGeometryEffect` namespace (`ns`), to avoid cross-interference between shape-morph tracking and glass-morph tracking |
| Scope — MUST be narrow | Wrap ONLY the `.glassEffect(...)` call inside `liquidGlassEffectLayer` itself. Do **NOT** wrap the whole `presentationSwitch`/view hierarchy — that exact wider scope was already tried and reverted (caused the entire island to read as permanently frosted glass, documented in `.planning/debug/resolved/liquid-glass-black-during-transition.md`). This is the single most important structural constraint in this contract |
| Same `glassEffectID` across all 4 shell call sites | Required so SwiftUI treats the glass as one continuous element across identity changes rather than tearing down/rebuilding it per call site |
| No pointer/cursor reactivity (D-05) | "Dynamic" means state-driven only (glass present through every animation/state transition). Do NOT build cursor-tracking distortion, mouse-follow highlight, or any live pointer-position input — explicitly ruled out even though the real macOS Dock and the 21st.dev reference both do this |
| Verification order | Fix D-04 FIRST against TODAY's already-working rim-only shape and confirm on-device the narrow-scoped fix holds under animation, THEN scale to full-surface coverage as a separate, later on-device-checkpointed step. This isolates whether any regression is caused by the container-scoping mechanism vs. the surface-area change (RESEARCH.md Pitfall 1) |

## Inner Elements Contract (D-06) — two risk tiers, per Apple's own navigation-vs-content glass guidance

None of these 6 elements currently share a render/code path with the shell or each other — treat each as its own separate integration point with its own on-device checkpoint, not one shared refactor.

### Tier 1 — Controls (safe for fuller glass intensity)

| Element | Current state | Glass treatment |
|---------|---------------|------------------|
| Quick Action buttons (`quickActionButton`, `NotchPillView.swift:2527`) | `RoundedRectangle(cornerRadius: 8)` background, `Color.white.opacity(enabled ? (isHovered ? 0.22 : 0.12) : 0.06)` | Apply `.glassEffect()` (or the chosen mechanism) to this existing background shape — do not replace the hover-brightness-step logic (D-11, Phase 34), layer glass underneath/alongside it. Disabled-state dim (`opacity(0.3)` on content, `0.06` fill) must remain visually distinct from enabled |
| View-switcher tabs (`navCircleButton`, `NotchPillView.swift:2796`) | Selected = solid white `Circle` fill + black glyph (high-contrast state indicator); unselected = `Circle().fill(.clear)` + white stroke outline | **Caution:** the selected state's opaque-white-fill/black-glyph IS the state signal — do not let glass treatment reduce the selected/unselected contrast to the point the active tab becomes ambiguous. Apply glass to the unselected/idle circle background (currently `.clear`) rather than diluting the selected state's solid white fill; if the executor's chosen mechanism also touches the selected state, D-02 (readability > glass intensity) governs — the selection signal is a readability-class requirement here, not a style preference |

### Tier 2 — Content surfaces (lower intensity, readability-first)

| Element | Current state | Glass treatment |
|---------|---------------|------------------|
| Calendar event cards (`EventRow`, `NotchPillView.swift:4717`) | Already has a card background: `RoundedRectangle(cornerRadius: 8)` fill `Color.white.opacity(0.06)`, plus a hover stroke overlay (D-16) | Layer glass onto this EXISTING card background — no new structural element needed here. Text (title, time) and the color-coded event dot must stay fully legible; this is the highest text-density D-06 element, treat as the primary legibility test case |
| Weather widget (`weatherFullContent`, `NotchPillView.swift:1954`) | **No existing card/tile background** — content (location, icon, temp, high/low) renders directly onto the island's own fill, no separate box | Requires a new lightweight card background to attach glass to (structural addition, not present today) — flag this explicitly to the planner; do not assume a card exists. Icon (44pt) and large temperature readout (32pt semibold) are the legibility-risk elements to verify first |
| Tray file tiles (`ShelfItemView.swift`) | **No existing tile background** — icon (40×40pt) + filename caption render directly, no box | Same structural gap as Weather: needs a new lightweight tile background to carry the glass layer. The existing delete badge (`xmark.circle.fill`, top-trailing overlay) must remain visually distinct on top of whatever glass tile is added — do not let it blend into the glass |

### OSD bars (D-07, simplified — stale premise corrected)

| Property | Value |
|----------|-------|
| Target | `OSDLevelBar` (`NotchPillView.swift:5048-5061`) |
| Current state | Plain, always-full-opacity `Capsule` fill — Phase 72.1's opacity-ramp mechanic (the thing D-07 originally said to "layer on top of") was REVERTED same-day (`260731-61m`) after on-device rejection. **There is no opacity ramp left to coordinate with.** |
| Contract | Apply the glass layer directly on top of `OSDLevelBar`'s current always-full-opacity fill. No ramp-layering logic needed — this simplifies D-07 to a single-layer addition |
| Color | `Color.green` (volume) / `Color.orange` (brightness) stay fixed, unchanged hue — glass affects the surface treatment only, never the semantic color (Phase 39 D-02 precedent, still locked) |
| Verify before planning proceeds | grep `ActivitySettings.swift`/`NotchPillView.swift` for `debugOSDOpacity` or similar before trusting any reference to "the opacity ramp" as live code — confirmed absent as of this research |

### Explicitly out of scope (D-08)

Settings window content and onboarding are NOT touched by this phase unless a shared code path is discovered during implementation — if so, flag back to the user before proceeding (Settings already has its own calmer glass variant from Phase 35 D-08/D-09, deliberately distinct).

## Layout / Spacing Contract

This phase is a material/fill rework — it introduces no new layout region, padding, or spacing constant for the island shell or the 4 elements that already have a background (Quick Action buttons, switcher tabs, EventRow, OSD bars). Existing geometry (pill/expanded/wings frames, `NotchShape` corner radii) is a locked constraint the glass layer must fit inside, never a reason to resize.

**Exception:** Weather widget and Tray file tiles currently have NO background box at all (see Inner Elements Contract above) — adding one is a small, necessary structural addition, not a redesign. Size/padding for these two new backgrounds is Claude's discretion at plan/execution time, but must:
- Stay inside each element's existing content frame (Weather: unbounded VStack today; Tray tile: `ShelfItemView`'s existing `VStack(spacing: 2)` + 40×40pt icon + `maxWidth: 56` caption)
- Not change icon/caption sizes, which are locked (Phase 32/TRAY-05 values)
- Follow the same `RoundedRectangle(cornerRadius: 8, style: .continuous)` convention already used by `quickActionButton` and `EventRow`, for visual consistency across all 6 D-06 elements

## Color

The "color contract" for this phase is a **material contract**, not a new accent palette — this mirrors Phase 35's own framing.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%+) | Existing `gradientMaterial`: `.black` (0%) → `.black` (~65%) → `.black.opacity(0.5)` (100%), top→bottom | Base fill direction — preserved unchanged, the glass layer composites on top, never replaces the gradient stops (D-02 in CONTEXT.md numbering) |
| Secondary (~30%) | Glass tint: `Color.black.opacity(0.7)` starting point (native `.glassEffect().tint(...)`) / retuned `edgeOpacity`/`centerOpacity` (legacy shader) | The frosted/glossy read across the WHOLE surface — this is what changes vs. today's rim-only look |
| Accent (~10%) | Specular highlight / rim-light stroke (exact mechanism is executor's discretion, D-01) | Reserved EXCLUSIVELY for the glass layer's own highlight/rim treatment — never repurposed as a decorative UI accent elsewhere, never conflated with the existing per-element `ActivitySettings.palette` accent colors (Now Playing/Charging/Device swatches), which this phase does not touch |
| Destructive | Not applicable | No destructive actions in this phase |
| OSD semantic colors | `Color.green` / `Color.orange`, fixed | Unchanged hue — glass is a surface treatment layered on top, per D-07 |

Accent reserved for: the glass layer's own specular/rim-light treatment only. Never applied to text, transport-control icons, the switcher's selected-state indicator fill, or the per-activity accent swatches.

## DEBUG Tuner Contract (established project convention — required for this phase)

Every prior Liquid Glass/material phase in this project needed on-device parameter tuning (Phase 35: 5 UAT rounds). Mirror the existing 3-file Wing Tuner pattern exactly (`ActivitySettings.swift` `@AppStorage` keys → `NotchPillView.swift` read points → `AppDelegate.swift` `NSMenu` actions, reusing the existing `adjustWingNudge(_:by:)`-style helper where the parameter shape matches).

| Tuner axis (minimum required) | Notes |
|---|---|
| Glass tint alpha | Starting baked value `0.7` (D-20-era) — nudge, don't hardcode a different literal |
| Glossiness parameter (whichever mechanism is chosen — specular strength / blur-clarity / rim-light brightness) | Executor's discretion which single knob or combination is exposed; at least one must be DEBUG-tunable |
| Legacy shader `edgeOpacity`/`centerOpacity`/`borderWidth` | For the `<macOS 26` fallback path — separate axis from the native-path tint, since the two paths are visually independent implementations |

Release builds: all new tuner nudges compile to `0`/unused via `#if DEBUG`/`#else`, zero behavior change outside DEBUG — matching every prior tuner axis (Phase 71 SHAPE-03, Phase 72.1 D-05).

## Interaction / Animation Contract

- The expand↔collapse spring morph (Phase 25 baseline) must not regress — the glass layer composites cleanly mid-morph with the D-04 fix in place: no visual artifacts, no dropped frames, verified on-device in the real never-focused panel.
- `.glassEffect()`/the legacy shader warps only Islet's own rendered fill layer — it does NOT bend or reveal the live desktop behind the transparent `NSPanel`. Do not design around or promise a live-background-warp/see-through effect (unchanged constraint from Phase 35).
- No live mouse/pointer-driven reactivity anywhere in this phase (D-05, restated above) — this is the one behavioral aspect of the 21st.dev reference that is explicitly NOT being ported.
- Idle-CPU cost: if the fuller-coverage glass has non-trivial idle cost while the island is visible but static, this is a watch-item during on-device UAT, not a hard blocking requirement (same framing as Phase 35).

## On-Device UAT Gate (hard merge gate, budget MULTIPLE rounds)

Per this project's own established pattern (Phase 35: 5 rounds for RIM-only glass alone) — this phase touches MORE surface area (shell + D-04 transition fix + 6 inner elements) — expect multiple checkpoints across the phase, not one checkpoint at the very end. Recommended sequencing per RESEARCH.md: fix D-04 against today's rim-only shape FIRST, verify, THEN scale to full-surface, THEN layer in the 6 D-06 elements.

- [ ] Island shell: glass reads across the WHOLE surface (pill/expanded/wings), not confined to a rim/edge (D-01)
- [ ] Island shell: text/icons/album art stay fully legible at all times — no unreadable glass bleeding into content (D-02/D-03)
- [ ] Transition continuity: no flat-black/flat-color frame during collapse↔expand morph (D-04) — reproduce the ORIGINAL bug fresh on today's code before verifying the fix (RESEARCH.md Open Question 3)
- [ ] Transition continuity: no flat-black/flat-color frame during tab switches (D-04)
- [ ] Transition continuity: no regression to the "whole island permanently frosted" failure mode from the previously-reverted wide-scope attempt
- [ ] Every island state shows glass: collapsed pill, mid-animation, compact expanded, full expanded (D-03)
- [ ] No cursor/pointer-follow distortion anywhere (D-05 — explicit negative check)
- [ ] Legacy (`<macOS 26`) fallback independently satisfies full-coverage + legibility (forced-branch verification, Pitfall 2)
- [ ] Quick Action buttons: glass applied, hover-brightness-step (D-11) still visually distinct, disabled-dim still visually distinct
- [ ] View-switcher tabs: selected vs. unselected state remains unambiguous after glass treatment
- [ ] Calendar event cards: text/time/color-dot fully legible with glass applied
- [ ] Weather widget: new card background + glass applied, 44pt icon and 32pt temperature readout fully legible
- [ ] Tray file tiles: new tile background + glass applied, delete badge stays visually distinct on top
- [ ] OSD bars: glass applied on top of the current always-full-opacity fill, green/orange hue unchanged
- [ ] `grep -c "liquidGlassEffectLayer(shape:" Islet/Notch/NotchPillView.swift` still returns exactly 4 (structural invariant — no new shell call site, per RESEARCH.md Validation Architecture)
