<objective>
Extend Liquid Glass to the two D-06 "Tier 1" control elements — Quick Action buttons (`quickActionButton`) and view-switcher tabs (`navCircleButton`) — per CONTEXT.md D-06 and UI-SPEC's Tier 1 contract (safe for fuller glass intensity, since these are navigation-layer chrome, not content).

Both elements already have a background fill that encodes state (hover/disabled for buttons, selected/unselected for tabs) — this plan wraps a NEW `.glassEffect(.regular.tint(...))` branch in an `if #available(macOS 26.0, *) { ... } else { ... }` guard around the existing `Color.fill(...)`, using the SAME opacity value the existing fill already used, so the state signal is preserved exactly (just rendered as real glass instead of a flat color on macOS 26+) rather than adding a second, separate glass layer alongside it. The project's deployment target is macOS 15.0 and `.glassEffect(_:in:isEnabled:)` is `@available(macOS 26.0, *)` — every existing `.glassEffect()` call site in this file (`NotchPillView.swift:750`, `:4561`) is guarded this same way, with a legacy fallback in the `else` branch; this plan follows that exact convention, not a bare unconditional call.

Purpose: Apply the phase's glass rework to the two lowest-legibility-risk D-06 elements first (controls, not content — RESEARCH.md Pitfall 3's own risk-tier ordering), compiling cleanly at the project's actual deployment target.
Output: Quick Action buttons and switcher tabs render with Liquid Glass backgrounds on macOS 26+ (plain fill unchanged below that); on-device UAT confirms hover/disabled/selected states stay unambiguous.
</objective>
