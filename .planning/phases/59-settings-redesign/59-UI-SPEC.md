# Phase 59 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** Islet is a native macOS SwiftUI app (`Islet/SettingsView.swift`). Not React/Next.js/Vite — the shadcn initialization gate does not apply, and there is no component-registry layer to detect. Design system is native SwiftUI (`Form`, `LazyVGrid`, `Toggle`, `.popover`) plus this codebase's own established typography/spacing/materials, extracted below from the file being restructured and from Phase 27/51's precedent UI-SPECs (the prior two Settings redesigns).

**Scope note:** This phase replaces `activitiesSection`'s flat `Form` toggle list with a categorized, 2-column `LazyVGrid` of `ActivityCard`s — 7 existing activities + 8 new (not-yet-built) v1.10 activities, all pre-wired with default-OFF persistence so their cards exist and are visibly "Neu"-badged ahead of their own implementation phases (60-67). It does NOT build any of the 8 new activities' actual island-content behavior — only their Settings card, toggle, and reserved resolver-priority slot.

## Grid Structure

### Categories (D-01, locked — exact header strings)

Three fixed categories, in this order, each its own `LazyVGrid`:

1. **System-HUDs**
2. **Medien**
3. **Produktivität**

Within each category: already-shipped activities first, then new v1.10 activities (D-03, locked).

### Category Assignment (D-07 + Claude's discretion for the 4 unassigned new activities)

D-07 locks 5 existing → System-HUDs, 2 existing → Medien, and names 4 of the 8 new activities as Produktivität examples (Timer/Pomodoro, Meeting-HUD, Quick Notes, Quick Actions bar) but leaves Caps Lock, Download-Progress, Menübar-Overflow, and Coding-Progress unassigned. Resolved here (flag for on-device UAT review per D-12's "review the result" process, same as icon/copy):

| Category | Existing (ordered first) | New (ordered after, "Neu"-badged) |
|----------|---------------------------|-------------------------------------|
| **System-HUDs** | Charging, Devices, Focus Mode, Volume & Brightness (OSD-Suppression), Calendar Countdown | Caps Lock, Download Progress, Menu Bar Overflow — grouped here because they are transient/ambient *system-state* signals, the same shape as Charging/Device/Calendar Countdown, not a user-productivity workflow |
| **Medien** | Now Playing, Song-Change Toast | — none |
| **Produktivität** | — none | Timer, Meeting HUD, Quick Notes, Quick Actions, Coding Progress — matches D-07's explicit 4-item list plus Coding Progress (a developer-workflow tool, the clearest "Produktivität" fit of the remaining 4) |

Card count per category: System-HUDs 8, Medien 2, Produktivität 5 = 15 total (7 existing + 8 new).

### Non-card items (D-05, locked)

"Launch Islet at login" and "Automatically Check for Updates" stay plain `Toggle`s in a `Form`, NOT cards — placed at the TOP of `activitiesSection`'s single shared `ScrollView`, above the 3 category grids, exactly where "Launch Islet at login" already sits today (minimal reordering). "Automatically Check for Updates" moves from inside the old `Section("Activities")` to this same top block, alongside Launch-at-login.

## Card Component Contract (`ActivityCard`, net-new)

One reusable view, `Islet/ActivityCard.swift`, rendering:

| Element | Spec |
|---------|------|
| Illustration icon | SF Symbol, 20×20pt, static (D-11 — explicitly NOT live-data) |
| Icon color | The activity's own customizable accent color (`ActivitySettings.accentColor(for:)`) for the 3 accent-configurable activities (Charging, Now Playing, Devices); `.secondary` (neutral gray) for all other 12 cards, which have no per-element accent control today |
| Title | 1 line, existing toggle label where one exists (e.g. "Charging", "Now Playing") or new short title for new activities |
| Description | 1 line, Claude-authored (D-12) — see Copywriting Contract table below |
| Toggle | `Toggle(isOn: Binding<Bool>)`, wired directly to the activity's `@AppStorage` property — no indirection (RESEARCH.md Pattern 1) |
| "Neu" badge | Small pill, top-trailing corner of the card, shown only when `ActivityCardData.isNew == true` (D-04) — text "Neu" |
| Options chevron | Optional `chevron.right` (or `ellipsis.circle`), shown only when `onOptionsTap` is non-nil (D-09/D-10) — this phase wires it for exactly 2 cards: Focus Mode, Volume & Brightness. All other 13 cards pass `nil` (chevron hidden entirely, not shown-disabled) |
| Card background | `RoundedRectangle(cornerRadius: 10)` filled with a subtle surface color — see Color section |

Options-chevron behavior (D-08, locked): tapping it on Focus Mode / Volume & Brightness opens the EXACT SAME existing popover views (`focusPermissionExplanationView`, `osdPermissionExplanationView`) already in `SettingsView.swift` today — relocated into the card, not redesigned, not moved to a separate detail sheet.

## Color

Native macOS system colors and materials only — no custom hex palette, matching Phase 27/51's precedent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | System window/`Form` background, or the Liquid Glass gradient/`.ultraThinMaterial` when `materialStyle == .liquidGlass` (existing `SettingsView.swift:237-254`, unaffected by this phase) | Detail-pane background behind the grid |

| Destructive | n/a | No destructive actions exist in this phase's scope (toggles only, no delete/reset) |

Accent reserved for: Toggle on-state, the 3 existing per-element accent icon colors, and the "Neu" badge fill — never applied to category headers, card titles, descriptions, or the options chevron (which stays `.secondary`).

## Verification Notes for Executor

- Every existing `@AppStorage` key NAME and DEFAULT LITERAL must stay byte-for-byte identical (SC4/SETTINGS-05) — this phase only changes presentation (Form row → card), never the persistence layer for the 7 existing keys.
- The 8 new keys must each default `= false`, with no exceptions (Pitfall 1) — do not copy-paste an existing `= true` declaration as a template.
- Keep exactly ONE `ScrollView(.vertical)` wrapping the entire `activitiesSection` body (plain-toggle block + all 3 category grids) — do not give the grid its own separate `ScrollView` nested inside another (Pitfall 3, mirrors Phase 51's own overflow-fix precedent).
- Do not build a generic dynamic/string-keyed `@AppStorage` — every toggle (existing and new) stays an individually-declared property; the card array is built from those properties' bindings at `body`-build time (RESEARCH.md Pattern 1, Anti-Patterns).
- Do not build a generic item-based popover router for the options-chevron — pass a plain `onOptionsTap: (() -> Void)?` closure, `nil` for 13 of 15 cards (RESEARCH.md Pattern 3, Don't Hand-Roll).
- Icon/copy choices above (all 15 titles, descriptions, icons, and the 4-activity System-HUDs/Produktivität category split) are Claude's discretion per D-12 and this file's own note — cosmetic, correctable during on-device UAT, not a blocking design decision.
- Card min-height (~84pt) and approx width (~195-205pt) are starting points for the executor's layout, not locked pixel values — confirm on-device once all 15 real cards render, per this project's established sizing-iteration convention.
- Reuse `ActivitySettings.palette`/`accentColor(for:)` exactly as it exists today for the 3 accent-configurable icons (Charging/Now Playing/Devices) — no new color-picker component.
