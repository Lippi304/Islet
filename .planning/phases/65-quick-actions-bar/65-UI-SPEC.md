# Phase 65 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — native macOS SwiftUI app (no `components.json`, no `package.json`, no web component registry) |
| Preset | not applicable |
| Component library | none — all controls are hand-rolled SwiftUI views in `Islet/Notch/NotchPillView.swift` (`navCircleButton`, `chipButton`, `wingsShape`, `blobShape`); Settings config reuses `ActivityCardData`/`ActivityCard` (`Islet/ActivityCard.swift`) and the `slotOptions`/`Picker` dropdown mechanism (`SettingsView.swift`, Phase 52) |
| Icon library | SF Symbols (`Image(systemName:)`) — `.symbolRenderingMode(.monochrome)` for every action tile (all 8 tiles are tappable/status glyphs, matching `downloadWings`'/Meeting-HUD's "tappable → prominent, not hierarchical" precedent, not the passive-content `.hierarchical` mode) |
| Font | System font, `design: .rounded` variant on every label (matches every existing wing/switcher/Settings label in this codebase); no `.monospacedDigit()` need this phase (no live numeric readout in the bar itself) |

This phase adds **zero new visual primitives**. Every control reuses an existing, on-device-proven pattern:
- The 8 action tiles are `navCircleButton`-style circles (36pt diameter, unchanged from onboarding/Timer precedent) arranged in a fixed 2-row × 4-column grid — NOT a new tile/button style.
- The Settings per-slot pickers are exact clones of Phase 52's `slotOptions` dropdown mechanism.
- The Settings card is the already-built `ActivityCardData(id: "quickActions", ...)` entry (`SettingsView.swift:255-258`) with `isComingSoon: true` flipped to `false` and a real `onOptionsTap` wired to a new popover (mirrors `quickNotesVaultPickerView`'s existing popover shape, not a new sheet style).

**Primary visual anchor:** the 8 action-tile grid itself — every tile reads at equal visual weight (no single "hero" action), since QACTION-01/02 treat all 8 catalog entries as equally-weighted, instantly-firing peers. The one exception is the two-directional icon-swap states (mic mute, dark/light mode, caffeinate) which read the same as their originating precedent (Phase 63's mic icon swap).

**Accessibility:** Every tile is icon-only with no visible text caption (matches Timer's 4-circle expanded row precedent). Each carries an explicit, state-dependent `.accessibilityLabel`:
- Mic: **"Mute Microphone"** / **"Unmute Microphone"** (verbatim reuse of Phase 63's exact label pair)
- Display Sleep: **"Sleep Display Now"**
- Dark/Light Mode: **"Switch to Dark Mode"** / **"Switch to Light Mode"** (label always names the mode you're switching *to*, matching the mic-label convention of naming the resulting action)
- Screen Lock: **"Lock Screen"**
- Do Not Disturb: **"Turn On Do Not Disturb"** / **"Turn Off Do Not Disturb"**
- Caffeinate: **"Keep Mac Awake"** / **"Allow Mac to Sleep"**
- Empty Trash: **"Empty Trash"**
- Launch slots (each independently configured): **"Open {app or URL display name}"** — the configured target's own name, never a generic "Launch App" label, so multiple launch slots remain distinguishable to VoiceOver users

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | not used this phase |
| sm | 8px | not used this phase |
| md | 16px | Row gap between the two 4-tile rows; bottom padding below row 2 |
| lg | 24px | Leading/trailing edge padding of the tile grid (both sides), matches this codebase's existing side-padding convention for switcher-row-hosted content |
| xl | 32px | not used this phase |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

Exceptions:
- **Tile diameter (36pt)** is a component size, not a spacing token — reused verbatim from `navCircleButton`'s existing `navCircleDiameter` constant (`NotchPillView.swift`). Do not invent a new diameter.
- **Column spacing** within each 4-tile row is NOT a fixed gap — tiles are distributed via `Spacer()` across the available content width, mirroring `switcherRow`'s existing evenly-spaced-circular-button pattern (`NotchPillView.swift:2571-2604`), not a hardcoded 16px/24px gap value. This keeps the grid visually centered regardless of exactly how many of the 8 slots are configured (see Copywriting Contract → empty-slot handling below).
- **`Self.cameraClearance` (42pt, existing shared constant)** — top padding before row 1 starts, identical to every other switcher-tab presentation (`homeEmptyContent`, `calendarContent`, `weatherFullContent`, `trayFullView`). Not on the 4px grid, not reinvented — reused exactly.

Starting geometry (planner/executor may retune on-device, must not invent a fresh starting point):
- Content box: reuse `Self.expandedSize.width` (420pt) — **no structural resize**, per D-01's explicit "purely a catalog addition, not a structural resize" instruction extended from the switcher row to this presentation's own content box.
- New `quickActionsContentHeight` constant, starting value **150pt** = `cameraClearance` (42) + row 1 tile (36) + row gap (16) + row 2 tile (36) + bottom pad (16) + 4pt rounding slack — close to but not identical to `Self.expandedSize.height` (144); add an explicit `.quickActionsBarExpanded` branch to `tabHeight`/`tabWidth` rather than falling through to the `default:` case (which is Home-shaped, not grid-shaped).

## Typography

Reuses exact size/weight pairs already established in `NotchPillView.swift` — no new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / secondary copy | 11px | regular (400) | 1.5 (empty-state hint text, DND setup hint) |
| Label / Settings dropdown row text | 13px | semibold (600) | 1.2 (matches `countdownWings`/Timer's label precedent) |
| Heading / empty-state title | 16px | semibold (600) | 1.2 (mirrors onboarding/Timer sheet-title precedent) |
| Display / empty-state icon glyph | 28px | n/a (icon, not text) | n/a (matches `homeEmptyContent`'s 28px `music.note` precedent) |

**Exactly 2 weights: regular (400) for secondary/hint copy, semibold (600) for everything else (labels, headings).** No bold/light/medium weights. The tile grid itself carries zero text — icon-only, per Accessibility above.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Black vertical alpha-gradient (existing shared shell material, VISUAL-01) | Pill/tab background — unchanged, this phase does not touch shell material |
| Secondary (30%) | `Color.white.opacity(0.12)` fill, `RoundedRectangle(cornerRadius: 8)` (existing `chipButton`/duration-chip convention) | Not used inside the tile grid itself (all 8 tiles are circles, not chips); reused only in the Settings popover's per-slot dropdown rows if a "selected" visual is needed, matching the existing chip convention |
| Accent (10%) | `Color.white` (full opacity) | Every tile's default (un-toggled/inactive) icon glyph and circle stroke — matches `navCircleButton(filled: false)`'s outlined-white convention. Reserved for: the 8 action-tile glyphs, the D-04 tap pulse flash, empty-state heading text. |
| Second semantic (red) | `Color.red` | **Reused verbatim from Phase 63's mic-mute convention** for exactly two states: (1) mic tile shows `mic.slash.fill` / red when muted (identical to Meeting-HUD); (2) DND/Focus tile's transient **failure** feedback — see Copywriting Contract for the exact treatment. Not used for any other tile, and never as a permanent "this feature is broken" indicator. |
| Second semantic (green) | `Color.green` | Reserved for exactly two tiles' **active/on** state fill: caffeinate (keep-awake currently engaged) and DND/Focus (confirmed-on via `INFocusStatusCenter` read-back) — mirrors this codebase's existing green-as-active-state convention (Pomodoro running-dot, charging ring). Dark/Light mode and Empty Trash have no persistent "on" state to color. |
| Destructive | none — not used | **Empty Trash is deliberately NOT color-coded red.** This codebase has zero precedent for color-coding destructive actions (Shelf's "Clear All," Timer's Stop/Reset both stay plain white/outlined). Empty Trash fires immediately on tap with the same D-04 pulse every tile gets — distinguished only by its `trash.fill` glyph, never a color or confirmation dialog (QACTION-02 explicitly forbids any dialog/expansion beyond the bar itself). |

Accent reserved for: all 8 tile glyphs (default state), the tap-pulse flash, empty-state heading. Red reserved for: mic-muted state, DND/Focus failure flash. Green reserved for: caffeinate-active state, DND/Focus confirmed-on state.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None.** Every tile fires its action immediately on tap (QACTION-02) — there is no separate "confirm"/"start" button anywhere in this phase, matching Meeting-HUD's "no manual start action" precedent. |
| Settings card (already implemented, flip `isComingSoon`) | Title: **"Quick Actions"** · Description: **"A row of one-tap system actions — mute mic, lock screen, and more."** (both already written in `SettingsView.swift:255-257` — no copy change needed, only `isComingSoon: false` + real `onOptionsTap`) |
| Settings popover title | **"Configure Quick Actions"** |
| Settings popover slot rows | **"Slot 1"** … **"Slot 8"**, each a `Picker` listing the fixed catalog + **"None"** (matches D-02's exact "catalog action or 'none'" wording) |
| Settings popover catalog labels | **"Mute Microphone"**, **"Sleep Display"**, **"Dark/Light Mode"**, **"Lock Screen"**, **"Do Not Disturb"**, **"Keep Awake"**, **"Empty Trash"**, **"Open App/URL"** (for each independently-configured launch slot, the picker additionally reveals an inline text field / `NSOpenPanel` "Choose App…" button, mirroring `quickNotesVaultPickerView`'s existing "Choose Folder…" pattern) |
| Empty state (zero of 8 slots configured) | Icon `bolt.horizontal.fill` (28px, `.white.opacity(0.4)`, matches `homeEmptyContent`'s dimmed-icon treatment) + Heading **"No Actions Configured"** + Body **"Pick up to 8 actions in Settings → Quick Actions."** — mirrors `homeEmptyContent`'s exact icon/heading/body structure and `cameraClearance`-based vertical placement. Configured slots (1-7 of 8) render only those tiles, evenly spaced — no empty placeholder tiles for unconfigured slots (matches this codebase's "don't render inert/empty UI" convention, e.g. HOME-03's full removal rather than a dimmed placeholder). |
| Error state — DND/Focus failure | The tile's icon briefly swaps to `exclamationmark.triangle.fill` tinted `Color.red` for ~1.2s (matching CAPS-01's ~1-2s transient-splash duration convention) before reverting to its normal `bell.slash.fill` glyph — fires only when the post-tap `INFocusStatusCenter` read-back (Research Pattern 2) confirms the toggle did NOT take effect. This is QACTION-03's required "failure visible, not silent" treatment. No text/alert — the icon swap alone is the signal, consistent with every other tile's icon-only design. |
| Error state — Screen Lock (no read-back possible) | None beyond the universal D-04 tap pulse — per research Pitfall 3, no public "is the screen locked" read API exists, so no failure detection is possible; the pulse confirms the tap registered, nothing more. Documented limitation, not a gap to fix this phase. |
| Destructive confirmation | **None for any of the 8 actions**, including Empty Trash — every tile fires immediately on tap with zero confirmation dialog, matching QACTION-02's literal requirement ("performs it immediately... without expanding the notch any further") and this codebase's existing no-confirmation precedent (Shelf Clear All, Timer Stop/Reset). |

## Tap Feedback (D-04, Claude's Discretion)

Uniform across all 8 tiles: on tap, the glyph scales `1.0 → 1.15 → 1.0` with a spring of **response 0.15, damping 0.86** — reused verbatim from Phase 39-08's OSD level-bar retune (D-16), this codebase's own already-proven "snappy single-press feel" constant, not a newly-guessed value. Paired with a brief opacity flash (`0 → 0.3 → 0` white overlay behind the glyph) on the same timing. Total perceived duration ≈ 0.3s (two spring half-cycles), well under CAPS-01's ~1-2s transient-splash scale since this is tap *acknowledgment*, not a status splash.

## Verification Notes (for gsd-ui-checker / executor)

- **Naming:** every new type/case must be prefixed `QuickActionsBar*` (e.g. `QuickActionsBarCatalog`, `.quickActionsBarExpanded`) — never bare `QuickAction*`, which collides with Phase 34's unrelated `QuickActionSharingService`/`.quickActionPicker(PendingDrop)` drag-drop destination picker (Research Pitfall 1).
- **Slot catalog membership:** Quick Actions is added to `slotOptions`' explicit 4-line `Label(...).tag(...)` list (5th line), NOT to `orderedSlotIcons`'s fixed-4-param signature and NOT as an unconditional always-shown tab — mirrors D-01, contradicts the more-recent Timer precedent (Research Pitfall 5).
- **DND/Focus tile must call `FocusModeMonitor.isAuthorized`** (existing static entry point), never duplicate authorization-request logic — and must NOT be gated on `ActivitySettings.focusKey`/the Phase 38 Focus HUD toggle; these are independent settings (Research Pitfall 4).
- **Empty/unconfigured slots render nothing** (no dimmed placeholder circle) — confirm the grid re-centers/re-spaces cleanly for 1-8 configured tiles, not just the 8-tile case.
- **Launch-slot URL/path validation:** the configured target must come from `NSOpenPanel`'s own return value or a validated `URL(string:)`, never raw typed text passed into a shell string — mirrors `quickNotesVaultFolderPath`'s existing discipline (T-64-07) and closes the AppleScript/command-injection threat flagged in RESEARCH.md's Security Domain section.
