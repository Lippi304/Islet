# Phase 63 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — native macOS SwiftUI app (no `components.json`, no `package.json`, no web component registry) |
| Preset | not applicable |
| Component library | none — all controls are hand-rolled SwiftUI views in `Islet/Notch/NotchPillView.swift` (`wingsShape`, existing wing functions: `capsLockWings`, `downloadWings`, `timerWings`, `countdownWings`) |
| Icon library | SF Symbols (`Image(systemName:)`), `.symbolRenderingMode(.hierarchical)` for the passive call icon, `.monochrome` for the interactive mute icon (state must read as fully opaque/prominent, matching Phase 61's `downloadWings` "brighter/more prominent" precedent for a tappable/status glyph) |
| Font | System font, `design: .rounded` variant on every label; the mm:ss elapsed text uses `.monospacedDigit()` to prevent width jitter as the number rolls (matches `timerWings`/`countdownWings`) |

This phase adds **zero new visual primitives** and **one new interaction primitive**: the first collapsed wing in this codebase with an actual tappable sub-region inside it (D-09). Every visual element (icon, text, wing shell) reuses an existing on-device-proven pattern; only the nested-tap-gesture mechanism (Research Pattern 3) is new.

**Primary visual anchor:**
- Collapsed pill: the live `mm:ss` elapsed-time text on the right flank — full-opacity white, the sole "glanceable value" content, mirroring Timer's countdown-digit precedent.
- The mute icon (far trailing edge) is the phase's one interactive element and carries the phase's only state-color signal (red when muted) — see Color below.

**Accessibility:** The mute icon carries an explicit `.accessibilityLabel`, state-dependent: **"Mute Microphone"** (when unmuted, tapping mutes) / **"Unmute Microphone"** (when muted, tapping unmutes) — mirrors Timer's Pause/Resume state-dependent label convention (`62-UI-SPEC.md`). The rest of the wing (call icon, elapsed text, background) is non-interactive and should NOT carry a redundant accessibility element beyond the wing's own implicit label — mirrors `downloadWings`' `.accessibilityElement(children: .ignore)` + single `.accessibilityLabel` pattern for the non-interactive portion.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between the mm:ss text and the mute icon (icon-to-value proximity, matches `updateWings`' `iconLabelGap`) |
| sm | 8px | not used this phase |
| md | 16px | Wing leading pad baseline (matches `downloadWings`/`timerWings` `leadingPad`) |
| lg | 24px | not used this phase |
| xl | 32px | Wing content height (`Self.wingsSize.height`, unchanged shared constant) |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

Exceptions: The collapsed-pill wing's camera-clearance **margin** (gap between wing content and the physical notch cutout) is not on the 4px grid anywhere in this codebase — arrived at through on-device measurement, never guessed. **`meetingWings(for:)` starts from `downloadWings`'/`timerWings`' non-Pomodoro `margin: 20` baseline** (Meeting-HUD's content — one icon left, mm:ss digits + one icon right — is the same "short, icon-adjacent" content class as those two wings, not the longer-text class `capsLockWings`/Pomodoro `timerWings` use at `margin: 65`). Retune on-device only if content is reported clipped or over-spaced, per project convention ("reuse a proven wing's constants instead of guessing widths iteratively").

Starting geometry (planner/executor may retune on-device, must not invent a fresh starting point):
- `leadingPad`: 16pt · `iconWidth` (call icon): 20pt · `margin`: 20pt · `rightContentWidth`: mm:ss text box 60pt (matches `timerWings`' non-Pomodoro countdown budget — same digit-count class) + 4pt gap + mute icon 20pt = 84pt · `trailingPad`: 12pt (matches `timerWings`' trailing pad)

## Typography

Reuses exact size/weight pairs already established in `NotchPillView.swift` — no new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / secondary copy | 11px | regular (400) | 1.5 (not used in the collapsed wing itself; reserved if a Settings-adjacent description is ever needed — the Settings card copy already exists, see Copywriting) |
| Label / wing icon glyphs | 13px | semibold (600) | 1.2 (call icon, matches `capsLockWings`/`timerWings` icon precedent) |
| Value / mm:ss elapsed text | 13px | semibold (600), `.monospacedDigit()` | 1.2 (matches `timerWings`/`countdownWings`' live-digit precedent exactly) |
| Mute icon glyph | 13px | semibold (600) | 1.2 (same size class as the call icon — both wing icons stay visually equal-weight) |

**Exactly 2 weights: regular (400) for any secondary/supporting copy (none appears in the collapsed wing this phase), semibold (600) for the call icon, mute icon, and mm:ss digits.** No bold/light/medium weights.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Black vertical alpha-gradient (existing shared shell material, VISUAL-01) | Pill/wing background — unchanged, Meeting-HUD does not touch shell material |
| Secondary (30%) | not applicable this phase | No secondary-surface element exists in a collapsed-only wing (no card/sheet/panel — D-10 locks Meeting-HUD to collapsed-only, never expanded) |
| Accent (10%) | `Color.white` (full opacity) | Call icon glyph (`.symbolRenderingMode(.hierarchical)`) and the mm:ss elapsed-text digits — the passive/glanceable content |
| Second semantic (red) | `Color.red` | **D-12 resolved: icon swap + red tint when muted.** The mute icon is `mic.fill` / white when the mic is live, swaps to `mic.slash.fill` / `Color.red` (`.symbolRenderingMode(.monochrome)`) when muted. Reuses this codebase's existing red-as-negative-state convention (validation error text, `urgencyColor(for:at:)`'s <60s countdown red) rather than inventing a new color — a red mic-slash is also the universal cross-app mute convention (Zoom/Teams/FaceTime all redden their own mute glyph), so this doubles as both an internally-consistent and externally-familiar signal. |
| Destructive | none — not used | Muting is instantly reversible (tap again to unmute) — not a destructive action. No confirmation, no separate destructive color beyond the red *state* signal above (which communicates "currently muted," not "about to destroy something"). |

Accent reserved for: the call icon glyph, the mm:ss elapsed-text digits, and the mute icon's white (unmuted) fill. Red reserved for: the mute icon's glyph + tint, muted state only.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None.** Meeting-HUD has no manual start action — it appears automatically per D-01's detection heuristic (app running AND mic active). The only user-facing control is the mute tap (icon-only, no text label — see Accessibility above for its screen-reader copy). |
| Wing content (collapsed, always) | Call icon (`video.fill`, non-interactive) + live `mm:ss` elapsed text (rolls past 59:59 as e.g. "75:32" per D-13, no h:mm:ss branch) + mute icon (`mic.fill`/`mic.slash.fill`, tappable) — no text label anywhere in the wing itself (matches `downloadWings`' icon-only precedent, not `capsLockWings`' text-label precedent) |
| Settings card (already implemented, Phase 59 grid — `SettingsView.swift:238-241`) | Title: **"Meeting HUD"** · Description: **"Shows a call timer and mic-mute control during Zoom/Teams calls."** · Icon: `video.fill` · Default: OFF (per SETTINGS-05) — description copy already correctly scopes to "Zoom/Teams calls" (not an unqualified "video calls"), which satisfies MEET-03's "documented as a known limitation, not silently missing" requirement for Google Meet's exclusion — **no further copy change needed**, confirmed by direct code read. |
| Empty state | Not applicable — Meeting-HUD has no dedicated empty view; it simply does not appear when no call is detected (D-08: immediate hide, symmetric with immediate show). |
| Error state | Not applicable — no user-facing error state exists for detection (silent no-show is correct behavior) or for the mute toggle (if `MicMuteController` fails per Pitfall 3, the icon should reflect the failure by staying in its pre-tap state rather than flipping — no error text, matches this codebase's "prefer showing nothing/disabled over confidently-wrong state" convention). |
| Destructive confirmation | **None.** Mute/unmute fires immediately on tap, exactly like every existing icon-only wing control in this codebase (no confirmation dialog anywhere in `NotchPillView.swift`). |

## Verification Notes (for gsd-ui-checker / executor)

- **D-09/D-10 interaction contract:** confirm at implementation time that `wingsShape`'s `onTap:` is set to an explicit no-op closure (`{}`, never `nil`) for `meetingWings(for:)` — leaving it `nil` falls through to the universal expand-to-Home every other wing uses, which D-10 explicitly forbids. The mute icon's own nested `.onTapGesture` (or `.highPriorityGesture` fallback per Research Pattern 3 / Open Question 3) is the ONLY interactive region.
- **Icon/text color desync risk:** the mm:ss elapsed text must be computed inside the same `TimelineView` tick closure as any state read (mirrors `countdownWings`' explicit warning against computing icon/text color outside a shared closure).
- **Mute icon state must come from the same source `MicMuteController` writes to** — read-after-write via `readSystemInputMuted()`, not an optimistic local toggle, so external mute changes (e.g. the user hits a hardware mute key) stay in sync (D-02's system-wide mute is observable outside Islet's own tap).
