  <what-built>
    A 4th "Convert" button in the Quick Action Destination Picker (Drop/AirDrop/Mail/Convert).
    Dropping only image files enables it; dropping any non-image file among the batch dims it.
    Tapping/releasing on the enabled Convert chip replaces the row with 4 format tiles (JPG/PNG/
    HEIC/TIFF) in the SAME card — not yet a commit. Releasing on a format tile converts every
    dropped image to that format and lands the converted copies in the Tray. Releasing off-target
    during either stage discards the pending drop. Separately, the pre-existing D-06 bug (a
    release on a dimmed AirDrop/Mail chip still firing its handler) is now fixed for all 4
    main-row buttons.
  </what-built>
  <how-to-verify>
    1. Drag a single JPG onto the collapsed island. Confirm the picker shows Drop/AirDrop/Mail/
       Convert, with Convert fully bright (enabled).
    2. Release on Convert. Confirm the SAME card now shows JPG/PNG/HEIC/TIFF tiles — no card
       resize, no conversion has happened yet (nothing lands in Tray at this point).
    3. Release on HEIC. Confirm the island collapses, the view switches to Tray, and a converted
       file appears there. Open it in Preview/Finder-Get-Info and confirm it is genuinely HEIC
       (not the original JPG renamed) — file size and Get Info "Kind" should read HEIC.
    4. Repeat steps 1-3 for PNG→TIFF and a multi-file batch (2+ images) → JPG, confirming ALL
       images in the batch convert and land.
    5. Drag one image + one non-image file (e.g. a .pdf) together. Confirm Convert renders
       DIMMED. Attempt to release on the dimmed Convert chip's screen position — confirm nothing
       happens (no format-tile stage appears, no conversion).
    6. Drag an image, release on Convert to enter the format-tile stage, then release somewhere
       inside the card but NOT on any tile (e.g. the empty margin). Confirm the pending drop is
       discarded (nothing lands in Tray) and the island collapses — same behavior as the
       existing main-row off-target-release.
    7. D-06 regression: drag any file, release on AirDrop or Mail in a context where you can
       visually confirm the chip renders dimmed (if reachable) — or, at minimum, confirm normal
       AirDrop/Mail taps still work exactly as before (no regression from the new gating code).
    8. Confirm ordinary (non-drag) hover/click behavior on the collapsed/expanded island is
       completely unaffected by this phase's changes.
