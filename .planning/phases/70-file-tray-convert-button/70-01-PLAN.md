<objective>
Build the two genuinely new pure/foundational pieces Phase 70 needs, plus one small shared
interface, before any UI or controller wiring touches them (interface-first ordering):

1. `ImageConversionService.swift` — the isolated ImageIO seam that converts an image file to
   JPG/PNG/HEIC/TIFF (D-02) and detects whether a URL is an image via `UTType` (D-05's detection
   foundation), mirroring `QuickActionSharingService.swift`'s "isolate the fragile thing"
   convention but WITHOUT its protocol/delegate/timeout machinery (conversion is synchronous,
   local, no OS UI).
2. Generalize `DragDropSupport.swift`'s `computeQuickActionButtonFrames(card:)` to
   `computeQuickActionButtonFrames(card:count:)` so it can compute frames for both the 4-button
   main row (Drop/AirDrop/Mail/Convert) and the 4-tile format row (JPG/PNG/HEIC/TIFF).
3. Add the `isShowingConvertFormats` stage flag to `IslandPresentationState.swift` — the shared
   contract both the Wave-2 UI plan (70-02, reads it to decide which row to render) and the
   Wave-2 controller plan (70-03, writes it on Convert tap) depend on.

Purpose: every later plan in this phase (70-02 UI, 70-03 controller wiring, 70-04 on-device
checkpoint) calls into these three artifacts directly — none of them re-derives conversion
logic, geometry math, or stage state independently.
Output: `ImageConversionService.swift` + its test file, `DragDropSupport.swift`'s generalized
function + extended tests, `IslandPresentationState.swift`'s new stage flag.
</objective>
