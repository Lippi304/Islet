**Analog:** this file's own `notchSize`/`topEdgeCutoutGap` (ISL-01 pure-function contract, doc comment lines 3-7)

// ISL-01 — pure notch geometry.
//
// These three functions take plain numbers (no live NSScreen), so the math is
// fully unit-testable. Plan 02 builds the NSScreen-backed wiring that feeds real

**Existing pure-function shape to mirror** (lines 64-74, `topEdgeCutoutGap` — nil-free, always returns a safe fallback):
```swift

                      safeAreaTop: CGFloat,
                      auxLeftWidth: CGFloat?,
                      auxRightWidth: CGFloat?,
                      widthFudge: CGFloat = 4) -> CGFloat {
    notchSize(screenWidth: screenWidth,
             safeAreaTop: safeAreaTop,
             auxLeftWidth: auxLeftWidth,
             auxRightWidth: auxRightWidth,
             widthFudge: widthFudge)?.width ?? 0
}
```

**New functions (RESEARCH.md Code Examples, already matched to this exact style — copy verbatim as the starting point):**
```swift
// D-06: locked baseline where today's fixed-pt constants read correctly.
func islandAutoScaleFactor(screenWidthPoints: CGFloat, baseline: CGFloat = 1470) -> CGFloat {
    guard baseline > 0, screenWidthPoints > 0 else { return 1.0 }
    return screenWidthPoints / baseline
}

// D-04: 80%-150% floor/ceiling applies to the EFFECTIVE (auto + manual) value, not the
// raw stored offset — matches ActivitySettings.accent(for:)'s existing defensive-clamp
// convention for an out-of-range palette index.
func resolvedIslandScale(auto: CGFloat, manualOffset: CGFloat, range: ClosedRange<CGFloat> = 0.8...1.5) -> CGFloat {
    min(max(auto + manualOffset, range.lowerBound), range.upperBound)
}
```
No error handling / try-catch needed — this project's pure-geometry layer uses guard-return-safe-default exclusively (see `notchSize`'s `guard ... else { return nil }` at line 32, `topEdgeCutoutGap`'s `?? 0` at line 73), never throws.

## Shared Patterns

### Pure-function-first geometry (ISL-01 contract)
**Source:** `Islet/Notch/NotchGeometry.swift` lines 1-7 (doc comment), `hasNotch`/`notchSize`/`topEdgeCutoutGap` (12-74)
**Apply to:** the new `islandAutoScaleFactor`/`resolvedIslandScale` functions — no live `NSScreen`, guard-based safe defaults, no throws.

### `@AppStorage` direct-read at the View, direct-`UserDefaults` read at the Controller
**Source:** `NotchPillView.swift` line 157 (`@AppStorage`) vs. `NotchWindowController.swift` line 1840/1881 (`UserDefaults.standard.string(forKey:)`)
**Apply to:** all 3 sites reading the two new manual-offset keys — View uses `@AppStorage`, Controller methods use `UserDefaults.standard.double(forKey:)` directly (no `@AppStorage` property wrapper available outside a View/ObservableObject in this codebase's convention).

### Geometry three-site rule (this project's own recurring precedent, cited 4+ times in RESEARCH.md)
**Source:** `NotchPillView.swift` (Site 1, `tabWidth`/`tabHeight`), `NotchWindowController.swift` `positionAndShow()` (Site 2) and `visibleContentZone()` (Site 3)
**Apply to:** every scaled constant — a change at one site without the matching change at the other two reintroduces the documented CR-01 click-swallowing/dead-zone regression class (hit in Phase 32/33/44/48/65).

### Settings-apply pipeline reuse (no new observer/re-host mechanism)
**Source:** `NotchWindowController.swift` `handleSettingsChanged()` (2907+) → ends in `renderPresentation()` + `updateVisibility()`; existing `didChangeScreenParametersNotification` observer (592-602)
**Apply to:** both the Settings-slider write path and the resolution-change auto-recompute path — neither needs new plumbing, both already trigger through this existing pipeline.

### Defensive clamp for a possibly-corrupted stored preference
**Source:** `ActivitySettings.accent(for:)` (lines 159-161, clamps an out-of-range palette index)
**Apply to:** `resolvedIslandScale`'s own `min(max(...))` clamp — the ONE shared clamp site for the manual-offset math, not ad-hoc `min(max(...))` scattered per call site.
