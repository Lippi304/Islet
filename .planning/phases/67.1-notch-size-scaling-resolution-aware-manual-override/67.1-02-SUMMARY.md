## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] NotchPillViewTests.swift's hardcoded width/height assertions broke on real hardware**
- **Found during:** Task 2's verification step (`xcodebuild test -only-testing:IsletTests/NotchPillViewTests`)
- **Issue:** The plan's own acceptance criteria expected the existing regression suite to pass unchanged "when resolvedWidthScale/resolvedDepthScale both equal 1.0 (baseline screen, no manual offset)". This machine's actual connected built-in display is not the 1470pt baseline, so `autoIslandScale` legitimately resolves to a non-1.0 value here — exposing that the tests hard-asserted absolute pixel values (420, 170, 472, 220, 650, 117, 290, 410) that are now genuinely screen-width-dependent by design (D-01's whole point). 19 assertions failed as a result.
- **Fix:** Rewrote both affected tests to compute the expected scale multiplier via the exact same pure functions production uses (`selectTargetScreen` + `islandAutoScaleFactor` + `resolvedIslandScale`, all already public/testable from Plan 01), multiplying every hardcoded expected constant by that live-derived scale instead of assuming identity. Both tests also reset the two manual-offset `@AppStorage` keys to 0 for their duration (mirroring the file's existing `weatherStyle`/`switcherLayout` isolation precedent) so a locally-configured Settings offset on the machine running the test can't desync the test's independently-computed scale from what `NotchPillView` itself resolves in the same process. One remaining assertion used exact equality across two independently-summed scaled totals and needed a small floating-point `accuracy:` tolerance (`0.0001`) — non-associativity of floating-point addition, not a logic bug.
- **Files modified:** `IsletTests/NotchPillViewTests.swift`
- **Verification:** `xcodebuild test -only-testing:IsletTests/NotchPillViewTests` — 8/8 green after the fix
- **Committed in:** `b172d6b` (Task 2 commit, same commit as the production scaling change since the test fix was required to prove Task 2's own acceptance criteria)
