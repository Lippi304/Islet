# Phase 67.1-06: Collapsed-Pill Live Re-Measurement Fix (D-09/D-10) Summary

**Diagnosed via real on-device trace that the collapsed pill's NSScreen-derived geometry was never stale — the mismatch was matchedGeometryEffect interpolating an ambient animation transaction; fixed by pinning `.animation(nil, value: size)` on the collapsed frame.**

## Performance

- **Duration:** ~45 min (includes waiting on user's on-device trace capture and UAT)
- **Tasks:** 4 (2 automated, 2 human checkpoints)
- **Files modified:** 2

## Accomplishments
- Added temporary `[D10-TRACE]` diagnostics at the 3 CONTEXT.md-flagged call sites, confirmed via Debug build.
- Captured a real on-device trace across a live resolution switch (1470×956 ↔ 1710×1112) in both directions.
- Trace showed `notify-immediate`, `notify-afterHop`, and `positionAndShow` all report the NEW resolution's NSScreen values on the very first notification firing — ruling out NSScreen-property staleness entirely (Case A, not the expected Case B AppKit-lag scenario).
- Implemented the Case A fix: `.animation(nil, value: size)` on `collapsedIsland`'s frame in `NotchPillView.swift`, preventing the live-measured pill size from riding along on any ambient animation transaction.
- Removed all temporary D10-TRACE diagnostics.
- User confirmed on-device: the collapsed pill now correctly and immediately matches the real camera cutout after a live resolution switch, in both directions, with D-09 non-regression (pill size unchanged across the manual Width/Depth sliders).

## Task Commits

1. **Task 1: Add temporary diagnostic trace instrumentation** - `165c526` (feat)
2. **Task 3: Diagnose root cause from the trace and implement the evidence-based fix** - `1c75b38` (fix)

_Task 2 and Task 4 were human checkpoints (no code changes)._

## Files Created/Modified
- `Islet/Notch/NotchWindowController.swift` - temporary D10-TRACE added then removed (net: no change vs. pre-plan state)
- `Islet/Notch/NotchPillView.swift` - `.animation(nil, value: size)` added to `collapsedIsland`'s frame chain, with a root-cause comment

## Decisions Made
- Root cause confirmed as render-layer (matchedGeometryEffect animation bleed), not the expected AppKit NSScreen-staleness — trace evidence directly contradicted the Phase-36 "settle re-poll" precedent pattern, so no retry/settle logic was added (would have been an unjustified guess per D-10's explicit instruction).
- Fix scoped narrowly to the `size` value only, so it does not suppress the collapse/expand `matchedGeometryEffect` morph or the hover `scaleEffect` spring, both driven by different values/transactions.

The core D-09/D-10 fix (bare collapsed pill shape matching the real camera cutout) was explicitly confirmed working by the user. Logged as a new deferred item for a future phase.
