# Phase 67.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

This phase's ONLY new visual surface is **two Settings sliders** (Width, Depth). Per D-01/D-02
(67.1-CONTEXT.md), the actual scale-factor math is a multiplier threaded through existing
`NotchPillView.swift` geometry constants — it introduces no new views, no new colors, and no
new typography in the notch itself. The collapsed pill is explicitly out of scope (D-02). This
contract therefore governs the Settings UI only.

Native macOS app (SwiftUI `Form`/`Settings` scene) — **not a web project**. No shadcn, no
Tailwind, no component registry. Template sections below are adapted to this project's existing
native design language (`Islet/SettingsView.swift`), not invented from scratch.

## Layout

```
Section("Island Size")
  LabeledContent("Width")  { Slider + trailing "NNN%" label }
  LabeledContent("Depth")  { Slider + trailing "NNN%" label }
  Text(caption, .footnote, .secondary)   // helper copy, see Copywriting Contract
  Button("Reset to Auto")                // trailing-aligned, .buttonStyle(.link) weight
```

- Each slider row mirrors the existing `LabeledContent("Now Playing") { swatchRow(...) }` pattern
  from Accent Colors — `LabeledContent(title) { Slider(...) }`, not a hand-rolled `HStack` layout.
- Slider control: native SwiftUI `Slider(value:in:)`, continuous (no discrete `step:`) — smooth
  drag feel. This is a **different control from OUTPUT-01's custom "thick draggable bar"**
  (that control lives inside the in-notch expanded Now Playing view, a different visual context);
  the Settings window uses plain native `Slider` like every other Settings control in this file.
- Range: 80%–150% (D-04), i.e. `Slider(value: $widthScale, in: 0.8...1.5)`.
- Value label: trailing, `Text("\(Int(widthScale * 100))%")`, `.monospacedDigit()` so the row
  width doesn't jitter while dragging.
- Live update: value applies immediately as the slider is dragged (no `.onEditingChanged`
  debounce) — matches this Settings window's existing immediate-apply convention (accent swatch
  tap, segmented Picker).

## Spacing Scale

No new spacing values are introduced — this phase adds two `LabeledContent` rows and one caption
inside the Form container `appearanceSection` already wraps in `.padding(20)`. Row spacing is
native `Form` row insets (system-managed), same as every existing row in `appearanceSection`.

| Token | Value | Usage |
|-------|-------|-------|
| Outer padding | 20px | Already established by `appearanceSection`'s `.padding(20)` — reused, not new |
| Row spacing | system Form default | Native `Form`/`Section` row insets — no custom `VStack(spacing:)` |

Exceptions: none.

## Color

No new colors. Sliders use the system accent color (macOS user-configurable tint), identical to
every other interactive control in this Settings window (`Toggle`, `Picker`, swatch-selection
ring) — no custom accent hex is introduced for this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | System window background | Settings pane background (unchanged) |
| Secondary (30%) | System `Form`/grouped background | Section container (unchanged) |
| Accent (10%) | System accent color (`Color.accentColor`) | Slider track fill/thumb, "Reset to Auto" link button — the only 2 elements |
| Destructive | not applicable | No destructive actions in this phase |

Accent reserved for: the slider fill/thumb and the "Reset to Auto" button only — matches system
control tinting, no bespoke color added.
