## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Islet process ↔ macOS Window Server / AppKit menu-bar layout engine | Islet writes only its own `NSStatusItem.length`/`autosaveName` (public API); no read/write of any other app's status item, no window enumeration, no cross-process memory access |
| Islet process ↔ local `UserDefaults` | Non-sensitive local Bool (reveal/hidden UI state) — no PII, no credentials, no cross-app data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-01 | Denial of Service | `clampedExpandedSpacerLength(candidate:screenWidth:)` | mitigate | Clamp result to `[0, max(screenWidth,0)]` so a degenerate/zero/negative screen-width read (external-display disconnect race) can never produce a negative or runaway `NSStatusItem.length` that corrupts menu-bar layout — covered by Task 1's 4 unit tests |
| T-66-02 | Tampering | `ActivitySettings.menuBarOverflowRevealedKey` (UserDefaults) | accept | A corrupted/tampered value degrades to `UserDefaults.bool(forKey:)`'s safe `false` default (hidden state) — no crash path exists; single local-user UI toggle, not a security boundary |
| T-66-03 | Elevation of Privilege | N/A — no Accessibility/permission surface in this design | accept | MENUBAR-04 is dropped (D-04); mechanism uses only public `NSStatusItem` API, no private CGS symbols, no synthetic events — eliminates the entire risk class the superseded Ice mechanism carried (see 66-01-SUMMARY.md NO-GO) |
</threat_model>
