Resolve the pre-existing D-02 conflict flagged by 66-PATTERNS.md: Phase 59's generic
"reserve-a-grid-slot" sweep already wired a disabled `isComingSoon: true` "Menu Bar Overflow"
toggle card (`ActivitySettings.menuBarOverflowKey`) into the Activities grid — but D-02 locks this
feature as having NO on/off toggle at all (it activates automatically once Accessibility is
granted). Remove that dead placeholder entirely, then build this phase's real Settings surface:
a persistent, always-visible permission-status card (D-04) inside the `.permissions` sidebar
section, distinct from the existing 5-item `permissionsSection` rollup.

Purpose: A toggle-shaped UI element for a feature that has no toggle is actively misleading —
worse than no UI at all. This plan replaces it with the one Settings surface D-04 actually
requires: live status + a deep link, nothing more.
Output: A clean Activities grid (8 cards again, not 9) + one new, accurate permission-status
Section.
