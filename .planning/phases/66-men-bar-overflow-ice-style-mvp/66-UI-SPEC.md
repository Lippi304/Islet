# Phase 66 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is a **menu-bar-chrome-only feature** (CONTEXT.md D-02/D-04/D-05/D-06, RESEARCH.md throughout). There is **zero notch/pill UI, zero popover, zero Settings surface** in this phase — the entire visual footprint is two `NSStatusItem` instances: (1) a visible chevron control (icon only, no text), (2) an invisible spacer whose `.length` toggles to genuinely reclaim/release menu-bar width. No permission-status card, no on/off toggle, no dropdown/popover reveal — CONTEXT.md explicitly forbids all of that for this feature (the old MENUBAR-04/D-04 permission gate is dropped). This contract covers exactly those two status items and nothing else.

## Spacing Scale

This phase has no SwiftUI content and no padding/margin surface — "spacing" here means `NSStatusItem` geometry, not a 4pt layout scale. Declared as the geometric equivalent:

| Token | Value | Usage |
|-------|-------|-------|
| Chevron item length | `NSStatusItem.variableLength` | Sized to its own icon glyph — identical construction call to the existing `statusItem`/`debugStatusItem` (`AppDelegate.swift:107`/`:490`) |
| Spacer collapsed length | 20pt | Hidden section is **revealed** (icons visible) — value from RESEARCH.md Pattern 1 (Hidden Bar's own `btnHiddenLength`) |
| Spacer expanded length | Clamped to the current screen's usable width (`NSScreen.main?.visibleFrame.width`), recomputed on every `NSApplication.didChangeScreenParametersNotification` (RESEARCH.md Pattern 3) | Hidden section is **hidden** — NOT a fixed constant; must be re-derived on display/resolution change per RESEARCH.md Pitfall 4. A rough reference ceiling is Hidden Bar's own ~2000pt, but the enforced bound is always "current screen width," not that literal number. |

Exceptions: none — no 4px-multiple padding/margin scale applies anywhere in this phase, since no SwiftUI content is rendered.

## Menu Bar Icon Contract (phase-specific — read before implementing)

### Chevron — two-state icon (Claude's Discretion, CONTEXT.md)

The chevron's glyph swaps with the hidden section's state, so its direction always signals what a click will do next (mirrors the existing mic-mute icon-swap convention from Phase 63/65, applied here for the first time to a menu-bar-only status item):

| State | Glyph | `accessibilityDescription` | When |
|-------|-------|------------------------------|------|
| Hidden section **hidden** (spacer expanded, icons off-strip) — **default on first launch** | `chevron.left` | `"Show Hidden Menu Bar Icons"` | No persisted UI state yet, or last-persisted state was hidden |
| Hidden section **revealed** (spacer collapsed, icons visible) | `chevron.right` | `"Hide Menu Bar Icons"` | User has clicked the chevron to reveal |

Both glyphs are template images (`isTemplate = true`), no `SymbolConfiguration` override — identical rendering convention to the existing `capsule.fill` icon. Rationale for defaulting to **hidden** on first launch: this is a "reduce menu-bar clutter" feature: starting in the reduced/hidden state matches the feature's own purpose and mirrors Hidden Bar's own default. Swapping this default later is a one-line change, not a design risk.

### Chevron placement & identity

- Leftmost among Islet's own menu-bar items (D-01) — constructed before/positioned left of Islet's existing `statusItem`.
- `autosaveName = "IsletMenuBarOverflowChevron"` — stable, hardcoded string (RESEARCH.md Pattern 2/Pitfall 1), so macOS's own position table anchors this item consistently across relaunches. Do not change this string once shipped — doing so resets the persisted position.
- No `NSMenu` attached, no click routing beyond `expandCollapseIfNeeded()`'s own left-mouse-up handling (RESEARCH.md's reconstructed `btnExpandCollapsePressed` shape) — clicking the chevron never opens a dropdown/popover (reaffirms D-05: reveal happens inline in the menu bar itself, not in a separate surface).

### Spacer — invisible, non-interactive

- No `button.image`, no `button.title` — the spacer must render as pure empty width, never a visible glyph or blank square.
- `button?.action = nil` (no click handling) — the spacer exists only to occupy width; all click handling lives on the chevron.
- `autosaveName = "IsletMenuBarOverflowSpacer"` — stable, hardcoded string, same rationale as the chevron's.
- `.length` toggles between the two values in Spacing Scale above — set directly, not animated (see next section).

### Reveal/hide animation (Claude's Discretion, CONTEXT.md D-05)

**None — instant width change.** Set `.length` directly with no interpolation, matching RESEARCH.md's reconstructed Hidden Bar reference exactly (`btnSeparate.length = isCollapsed ? btnHiddenLength : btnHiddenCollapseLength`, no animation code). `NSStatusItem.length` is not natively animatable the way a SwiftUI frame is — animating it would require a hand-rolled `Timer`/`CADisplayLink` interpolation loop, which is unproven complexity for an MVP menu-bar mechanic with zero user request for motion here. This is a deliberate simplification, not an oversight — revisit only if on-device UAT (RESEARCH.md Pitfall 3's end-of-task checkpoint) finds the instant toggle visually jarring in practice.

### Islet's own items — exempt by construction, not enforcement

Per CONTEXT.md's default discretion assumption and RESEARCH.md Pitfall 2: Islet's own existing `statusItem`/`debugStatusItem` are positioned to the right of the spacer at construction time (visible zone) but are **not** programmatically prevented from being Cmd-dragged behind it — no public API exists for that. No self-heal check (RESEARCH.md Pattern 4) is built for this MVP (YAGNI — Open Question 2's recommendation). Do not add copy or UI promising unhideable icons; this is a positioning default, not an enforced guarantee.
