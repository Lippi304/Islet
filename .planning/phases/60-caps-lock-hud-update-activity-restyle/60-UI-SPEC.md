# Phase 60 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** Islet is a native macOS SwiftUI app. Not React/Next.js/Vite — the shadcn initialization gate does not apply, and there is no component-registry layer to detect (confirmed: no `components.json`/`tailwind.config.*` anywhere in the repo). Design system is native SwiftUI (`wingsShape`, SF Symbols, San Francisco system font) plus this codebase's own established wing/permission-popover conventions, extracted below from `NotchPillView.swift`/`SettingsView.swift` and this phase's own `60-CONTEXT.md`/`60-RESEARCH.md`.

**Scope note:** Two new collapsed-only transient wings, both built from scratch (D-01: there is no existing Update HUD to reskin — Phase 40's original was deleted) but both structurally cloning the already-approved `wings(for:)`/`focusWings(for:)` shape. This spec does NOT touch the menu-bar update dot (kept unchanged, D-02) and does NOT redesign Sparkle's install flow.

## Caps Lock Wing Contract (CAPS-01)

**Structural constraint:** renders via the existing `wingsShape(leftWidth:rightWidth:)` helper — same split-wing structure as Charging/Focus/OSD. No new shape.

**Visibility constraint (D-07, locked):** collapsed-only — the wing never renders while the island is expanded (same rule as Focus/OSD). Auto-dismisses ~1.5s after the Caps Lock key is pressed (mirrors OSD's `osdActivityDuration` self-elapsing timer, shortened per CAPS-01's "~1-2s" wording) — no manual dismiss control, no persistent state.

**Key difference from every other wing (D-03, locked):** both the ON and OFF states show icon **and** text label — there is no icon-only variant. This is the one wing in the codebase where the "positive state only shows a label" convention (Charging/Focus) does NOT apply.

### Left wing (icon only)

| Property | Value |
|----------|-------|
| Width | `Self.wingsSize.width / 2` (145pt) — fixed, no text on this side, matches Charging's non-charging-state left width |
| Icon | `Image(systemName: "capslock.fill")`, `.font(.system(size: 13, weight: .semibold))`, `.symbolRenderingMode(.hierarchical)` |
| Icon color | `Color.white`, fixed in both ON and OFF states — never theme-accent-tinted (mirrors Focus's D-11 precedent: a universal system-level signal should read consistently regardless of the user's chosen accent color) |
| Left padding from notch edge | 12px — reused verbatim from `wings(for:)`/`deviceWings(for:)` |

### Right wing (label text)

| Property | Value |
|----------|-------|
| Width | `Self.wingsLabelWidth / 2` (200pt) — widened past the default 145pt so the text clears the physical camera cutout, mirroring the Countdown wing's own established fix (`41-01` gap-closure: `wingsLabelWidth/2` used specifically because label text — not just an icon — sits on that side) |
| Label text (ON) | `"Caps Lock On"` |
| Label text (OFF) | `"Caps Lock Off"` |
| Label style | `.system(size: 12, weight: .semibold, design: .rounded)`, `Color.white` — identical spec to every other wing's label, fixed in both states (no dimming, no accent) |
| Right padding from notch edge | 14px — reused verbatim from `wings(for:)` |

**No status dot, no color-coded ON/OFF distinction beyond the text string itself.** Do not invent a colored indicator circle for this wing — D-03's requirement is legibility of the state via text, which the two distinct strings already satisfy; adding a redundant dot is unrequested scope.

## Update Wing Contract (UPDATE-01)

**Structural constraint:** renders via the existing `wingsShape` helper. No new shape — but `wingsShape` itself gains one new optional parameter this phase (see Interaction Contract below).

**Visibility constraint (D-07, locked):** collapsed-only, same rule as Caps Lock. No "no update" state to design — the wing simply isn't in the view tree when `updateAvailable` is nil, same as Charging's unplugged state.

**Lifecycle:** self-elapses via the shared default transient duration (~3s, no shorter override is locked for this HUD, unlike Caps Lock's ~1-2s) — after it disappears, the persistent menu-bar red dot (unchanged, D-02) remains the durable, always-available affordance to actually open the update dialog later. The island HUD is a brief *notification*, not the only path to act.

### Left wing (icon + label — always both, since the wing only ever exists in the "update available" state)

| Property | Value |
|----------|-------|
| Width | `Self.wingsLabelWidth / 2` (200pt) — mirrors Charging's `isCharging` branch width, since "Update" text needs room |
| Icon | `Image(systemName: "arrow.triangle.2.circlepath")`, `.font(.system(size: 13, weight: .semibold))`, `.symbolRenderingMode(.hierarchical)`, `Color.white` |
| Label | `"Update"` — `.system(size: 12, weight: .semibold, design: .rounded)`, `Color.white`, always shown (no icon-only variant, since the wing has no negative state) |
| Left padding from notch edge | 12px — reused verbatim |

### Right wing (trailing version pill — new small component, `UpdateVersionPill`)

| Property | Value |
|----------|-------|
| Width | `Self.wingsSize.width / 2` (145pt) — same right-width convention as Charging's `BatteryIndicator` slot |
| Content | `"v\(item.displayVersionString)"` (D-04, locked — e.g. `"v1.11"`), sourced from `SUAppcastItem.displayVersionString` |
| Visual language | Derived from `BatteryIndicator`'s styling, NOT its content (D-04) — compact rounded pill, no fill bar, no percentage: `RoundedRectangle(cornerRadius: 4)` fill `Color.white.opacity(0.15)`, stroke `Color.white.opacity(0.3)` width 1, fixed height 16pt, horizontal padding 8pt (auto-sizing width to content, no hardcoded width) |
| Text style | `.system(size: 11, weight: .semibold, design: .rounded)`, `.monospacedDigit()`, `Color.white` |
| Right padding from notch edge | 14px — reused verbatim |

**Do not reuse `BatteryIndicator` itself as a component** — it has no equivalent "level"/fill concept for a version string; build `UpdateVersionPill` as its own small view that borrows only the visual weight (compact, rounded, legible small text), per RESEARCH.md's explicit Don't-Hand-Roll guidance.

## Update Wing Interaction Contract (Pattern 2 in RESEARCH.md — net-new territory)

**This is the one wing in the codebase whose tap action is NOT "expand to Home."**

| Property | Value |
|----------|-------|
| Tap target | The entire Update wing (both left and right regions) — single unified tap zone, matching every other wing's full-wing tap area |
| Tap action | Triggers Sparkle's update-install flow (opens Sparkle's own standard update dialog — reuse whatever `SPUStandardUpdaterController` call the app already exposes elsewhere; no custom install UI to design) — NOT expand-to-Home |
| Mechanism | `wingsShape` gains an optional `onTap: (() -> Void)? = nil` parameter, defaulting to the existing `onClick()` (expand-to-Home) behavior when `nil`, so Charging/Device/Focus/OSD/Caps Lock are unaffected. Only `updateWings(for:)` passes a non-nil override. |
| Risk flag (Pitfall 4, carried from RESEARCH.md, not a visual concern but binds the tap-target contract) | The click-through hot-zone/rendered-wing-geometry sync that broke Phase 40's original badge is a real, unresolved risk for this specific wing since its tap action is genuinely new (every other wing's tap is forgiving of small hit-test misses because any tap does the same universal thing). Executor must add an on-device tap-target verification step before considering this wing done — not a UI-SPEC concern to redesign around, just do not skip that check. |

## Layout Contract (replaces "Spacing Scale")

This phase touches only the collapsed-pill wing geometry (fixed pixel constants, not a generic 8pt scale — matches every prior wing-adding phase's convention, e.g. `38-UI-SPEC.md`, `41-UI-SPEC.md`) and one Settings popover (reuses the exact existing popover frame).

| Region | Value | Source |
|--------|-------|--------|
| Wing height | `Self.wingsSize.height` (32pt) — unchanged, every wing shares this | Existing constant |
| Caps Lock left width | 145pt (`wingsSize.width / 2`) | Existing constant, icon-only side |
| Caps Lock right width | 200pt (`wingsLabelWidth / 2`) | Existing constant, text-bearing side (Countdown-wing precedent) |
| Update left width | 200pt (`wingsLabelWidth / 2`) | Existing constant, icon+label side |
| Update right width | 145pt (`wingsSize.width / 2`) | Existing constant, compact-pill side |
| Wing left/right edge padding | 12px / 14px | Reused verbatim from `wings(for:)` throughout |
| Version pill height | 16pt (new) | New value, multiple-of-4 rounding to nearest existing convention (BatteryIndicator body is 13pt; 16pt gives slightly more room for "v1.11"-length text without a fill bar) |
| Version pill horizontal padding | 8pt | Standard 8-point scale value (revised from an earlier 6pt draft — 8pt is on the codebase's 4/8/16/24/32/48/64 scale; width auto-sizes to content, so the extra 2pt only adds room and cannot cause "v1.11"-length text to clip) |
| Permission popover frame | `.frame(width: 280)`, `.padding(16)` | Reused verbatim from `osdPermissionExplanationView` |

Exceptions: version pill's 16pt height is a new value not reused from an existing constant — flag for on-device tuning if "v1.11"-length strings don't fit comfortably, per this project's established sizing-iteration convention (Phases 18/20/21/23/25/26/32/33/51/52 all tuned dimensions post-implementation). Horizontal padding (8pt) is no longer an exception — it is a standard spacing-scale value.

## Verification Notes for Executor

- **Caps Lock wing:** new `capsLockWings(for:)` in `NotchPillView.swift`, structurally cloning `wings(for:)`/`focusWings(for:)` — reuse `wingsShape`, `Self.wingsLabelWidth`/`Self.wingsSize` constants verbatim, do not invent new sizing constants beyond the version-pill exceptions noted above.
- **Do not add a colored status dot to the Caps Lock wing** — D-03 is satisfied by the two distinct text strings alone; an extra dot is unrequested scope (ponytail: the text already conveys state, a redundant color cue adds a second thing to keep in sync for no legibility gain).
- **`wingsShape`'s new `onTap` parameter must default to `nil` → existing `onClick()` behavior** — Charging/Device/Focus/OSD/Caps Lock call sites must NOT need to change to accommodate this; only `updateWings(for:)` passes a real override. If any existing call site needs editing to keep compiling, that's a sign the parameter was added wrong (should be purely additive/optional).
- **`capsLockPermissionExplanationView` is a NEW popover, not a shared/generalized one with OSD's** — same permission bucket (Accessibility), same visual shape, but its own instance with Caps-Lock-specific copy, mirroring how Focus and OSD each have their own popover today despite structural similarity.
- **Update HUD's tap target is the highest-risk item in this phase visually** (Pitfall 4) — it is the first wing since Phase 40's abandoned badge to have a non-universal tap action. Add an explicit on-device tap-reliability check (repeated taps across the wing's rendered area, zero click-through) before marking UPDATE-01 visually complete — this is a verification gate, not a redesign trigger.
- **`UpdateVersionPill` is a new, small, standalone view** — do not attempt to parameterize `BatteryIndicator` to also handle a version-string mode; the fill-bar/percentage concept doesn't map cleanly and forcing it in risks destabilizing the already-proven Charging/Device battery displays.
- **Version pill padding is 8pt (revised from an earlier 6pt draft)** — since the pill auto-sizes width to content, this only adds ~4pt of total width versus 6pt; on-device check "v1.11"-length text still during implementation, but there is no reason for the wider padding to cause any clipping the narrower value wouldn't already have avoided.
- Both wings' fixed-white (never theme-accent) color choice is deliberate (matches Focus's D-11) — if a reviewer expects Phase 59-style per-element accent theming here, that's a mismatch with this spec, not a bug in the implementation.
- Icon choices (`capslock.fill`, `arrow.triangle.2.circlepath`) are locked by this spec, not left to further discretion — `capslock.fill` was already used in Phase 59's Settings card copy, so reusing it here keeps the card and the live wing visually consistent.
