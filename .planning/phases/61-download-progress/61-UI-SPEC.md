# Phase 61 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — native macOS SwiftUI app, no web/shadcn stack, no `components.json` present |
| Preset | not applicable |
| Component library | none — custom in-house `wingsShape()` HUD helper (`Islet/Notch/NotchPillView.swift:2310`), reused verbatim, no new shape |
| Icon library | SF Symbols via `Image(systemName:)` |
| Font | SF system font, `.system(size:weight:design:)` — `.rounded` design for the label text (matches every sibling wing: Charging/Caps-Lock/Update) |

This phase adds **zero new visual primitives**. Per 61-CONTEXT.md's own "Specific Ideas": *"the wings pattern, with a spinner instead of a battery/version pill — no new shape, only new content."* This spec is a content contract layered onto the existing `wingsShape()`/`capsLockWings(for:)`/`updateWings(for:)` precedent (Phase 60), not a new design system.

## Spacing Scale

This is a small transient collapsed-HUD element, not a page layout — it reuses the exact pixel constants already established by the sibling wings (`capsLockWings`/`updateWings`, `NotchPillView.swift:2879-2966`), all of which are already 4pt-multiples:

| Token | Value | Usage |
|-------|-------|-------|
| leadingPad | 12px | Left inset before the icon (matches `capsLockWings`) |
| iconLabelGap | 4px | Gap between icon and label text (matches `updateWings`'s `iconLabelGap`, widened slightly from its 2px since "Downloading…" is longer than "Update") |
| iconWidth | 20px | Icon glyph frame width (matches every sibling wing) |
| trailingPad | 12px | Right inset after the trailing element |
| wingsSize.height | 32px | Fixed HUD height — `Self.wingsSize.height`, untouched |

Exceptions: none — no new spacing values introduced, all borrowed from the existing wings constants.

## Typography

This HUD shows exactly one line of label text at a time (never both states simultaneously) — matching the sibling wings' single-`Text` convention. No heading/display/body roles apply to a transient collapsed HUD.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Wing label (only role used) | 12px | semibold | 1.0 (single line, `.lineLimit(1)`) |
| Icon glyph | 13px | semibold | n/a (SF Symbol, not text) |

Body/Heading/Display: not applicable — this phase renders inside the existing collapsed-HUD wing only (D-03: collapsed-only), never inside an expanded page layout.

## Color

This phase touches only the shared black-gradient shell material (Phase 25, unchanged) — no new surface colors. The "60/30/10" full-page split doesn't apply to a single-line transient HUD; the contract below instead pins every element's specific color.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (shell material) | existing black→transparent gradient (Phase 25, `blobShape`/`wingsShape` material) — unchanged | Wing background |
| Icon + label default | `Color.white` | Leading icon + label text, both states (matches Caps-Lock/Update precedent: no state-color tinting for a non-charging, non-alarm activity) |
| Accent (done-state only) | `Color.green` | **Reserved for exactly one element**: the done-state's `checkmark.circle.fill` icon — matches this project's existing green-for-success convention (Charging bolt, OSD volume bar). Never applied to the in-progress spinner or label. |
| Destructive | not applicable | No destructive action in this phase (D-11: no tap action; D-15: failed/cancelled downloads silently disappear with no UI at all, no error color) |

Accent reserved for: **the done-state checkmark icon only** — never the spinner, never any text, never the in-progress icon.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | not applicable — D-11 locked: no tap action anywhere in this HUD, purely informational |
| In-progress label (locked, D-09) | `"Downloading…"` — generic, fixed string, never the filename (avoids truncation/overflow on long/ugly temp filenames) |
| Done-state label (locked, D-12) | The real final filename (post-rename), e.g. `"invoice.pdf"` — rendered with `.lineLimit(1)` + `.truncationMode(.middle)` inside a fixed max width as a safety net for unexpectedly long final filenames (default: not explicitly locked by CONTEXT.md, this truncation behavior is this spec's recommended default) |
| Empty state | not applicable — this activity has no empty/idle visual state; it simply doesn't appear in the `TransientQueue` when no download is active |
| Error state | not applicable by explicit design — D-15 locked: a cancelled/failed download (temp file deleted without rename) silently disappears with **no** done state, no error text, no error icon |
| Destructive confirmation | not applicable — no destructive actions in this phase |

## Icon & Layout Contract (phase-specific content, layered onto `wingsShape()`)

Mirrors `capsLockWings(for:)`'s fixed-camera-block math (`NotchPillView.swift:2879-2914`) since — like Caps Lock — both flanks carry real content that must clear the physical camera cutout.

**In-progress state** (leading icon + generic label, trailing spinner):
| Element | Spec |
|---------|------|
| Leading icon | `Image(systemName: "arrow.down.circle")`, 13pt semibold, `.symbolRenderingMode(.hierarchical)`, `.foregroundStyle(.white)`, 20pt-wide frame |
| Label | `Text("Downloading…")`, 12pt semibold rounded, white, `.lineLimit(1)`, fixed frame ~100pt (fixed string, no dynamic width — same footprint math as `capsLockWings`' `textWidth`) |
| Trailing element (replaces battery/version pill per CONTEXT.md's own framing) | `ProgressView()` circular spinner, `.controlSize(.small)`, tinted white via `.tint(.white)`, ~20pt frame — SwiftUI's native system spinner (Claude's Discretion per 61-CONTEXT.md: "SwiftUI system spinner vs. a small custom one — low-stakes, pick whatever matches the wings pattern's existing trailing-element sizing"). Default chosen: **native `ProgressView()`**, not a custom-drawn spinner — smallest-diff option that already matches the sibling wings' trailing-element size budget. |
| No tap override | `onTap` param omitted (nil) per D-11 — but since this HUD is purely informational with no tap semantics at all (unlike Update's Sparkle-trigger override), the universal `onClick()` expand-to-Home fallback simply applies like Charging/Caps-Lock (D-11 only rules out a *custom* action, not the pre-existing universal tap-to-expand) |

**Done state** (leading checkmark + real filename):
| Element | Spec |
|---------|------|
| Leading icon | `Image(systemName: "checkmark.circle.fill")`, 13pt semibold, `.symbolRenderingMode(.hierarchical)`, `.foregroundStyle(.green)` — the phase's one accent-color use, 20pt-wide frame |
| Label | `Text(finalFilename)`, 12pt semibold rounded, white, `.lineLimit(1)`, `.truncationMode(.middle)`, fixed max frame ~140pt (wider than the in-progress label's fixed 100pt since filenames vary; middle-truncation preserves the file extension) |
| Duration | ~3s auto-dismiss (D-13, already locked — not a visual question, restated here only for the executor's layout-timing context) |

Both states share the identical `wingsShape(leftWidth:rightWidth:)` call shape and `wingsSize.height` (32pt) — no shape change between in-progress and done, matching every prior wings transition (Charging, Caps Lock, Update).
