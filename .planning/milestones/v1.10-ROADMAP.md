# Milestone v1.10: Live Activities Suite

**Status:** ✅ SHIPPED 2026-07-30 (with known gaps)
**Phases:** 59, 60, 61, 62, 63, 65 (of 59-67 originally scoped — 64/66/67 carried forward, not shipped)
**Total Plans:** 28

## Overview

Adds a suite of new Live Activities/HUDs inspired by Droppy and the open-source Ice, plus a
Droppy-style Settings grid overview to manage all Live Activities (existing + new) in one place —
most new activities default OFF rather than opinionated-on. Started 2026-07-23 while v1.4, v1.5,
and v1.7 all remained open in parallel (explicit user decision).

**Scope correction at close:** originally defined as Phases 59-67 (9 phases). At close-out
(2026-07-30), Phase 63 was formally goal-backward verified and shipped. Phase 64 (Quick Notes)
was found to have 3 unfixed major on-device UAT bugs plus 2 approved-but-unbuilt scope changes;
Phase 66 (Menübar-Overflow) remained PAUSED after 3 consecutive on-device NO-GOs; Phase 67
(Coding-Progress) was never started. All three are carried forward, not descoped — see Known
Gaps below.

## Milestone Summary

**Not shipped (carried forward, not descoped):**

- **Phase 64: Quick Notes + Obsidian Export** — all 8 plans executed, but on-device UAT (`64-UAT.md`) found 3 major bugs never fixed (no keyboard focus on popover open, delete button unclickable once the history list is scrolled, empty-state popover doesn't close) plus 2 user-approved scope changes never built (delete-from-vault-file, file browser/switcher). Needs `/gsd:plan-phase 64 --gaps`.
- **Phase 66: Menübar-Overflow (Debug-the-CGS-Spike MVP)** — PAUSED by user 2026-07-28 after 3 consecutive on-device NO-GOs across two structurally different mechanisms (private CGS window enumeration, then public `NSStatusItem` chevron+spacer); even the reference implementation (Ice.app) failed identically on the third attempt. Root cause unconfirmed — possible macOS 27 "Golden Gate"/Developer Mode regression, untestable without a full macOS 26 downgrade. No revisit trigger set; feature still wanted.
- **Phase 67: Coding-Progress** — never started, no phase directory exists. Not blocked on anything — simply not reached before Phase 70 (a queued backlog idea) was worked ahead of it per explicit user priority (2026-07-29).

**Key Decisions:**

- D: Generalize `TransientQueue.preempt()`/`ActiveTransient.isPersistent` in Phase 62 (Timer) before reusing it in Phase 63 (Meeting) — validate the pattern on the simpler no-detection-risk case first.
- D: Meeting-HUD's D-05a — nothing interrupts a live call (supersedes the original plan of Charging/Device-only interruption), discovered via on-device UAT round 1 failure.
- D (2026-07-30, milestone close): Phase 63's 3 post-UAT code-review fixes accepted as code-verified/test-green without a live on-device re-test, rather than blocking the milestone on a fourth UAT round.
- D (2026-07-30, milestone close): Phases 64/66/67 carried forward rather than force-closed with fabricated pass states — matches this project's own Phase 22/49/66-pause precedent of honest partial-ship over inflated completion.

**Issues Resolved:**

**Issues Deferred:**
