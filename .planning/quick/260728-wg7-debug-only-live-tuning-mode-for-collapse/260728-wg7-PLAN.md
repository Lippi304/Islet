<objective>
A DEBUG-only live-tuning mechanism for the collapsed-state HUD "wings" (Now Playing,
Brightness/Volume OSD, DND/Focus, Caps Lock, Charging, Device, Update, Download, Timer,
Countdown, Meeting — every `wingsShape()`-based collapsed glance in `NotchPillView.swift`).
Instead of "user reports X looks wrong -> Claude guesses a new constant -> rebuild -> repeat",
the user gets 4 generic live nudge axes (Leading pad, Trailing pad, Margin/camera-clearance,
Icon/text gap) driven from the existing 🐞 debug status-bar menu (`AppDelegate.setupDebugMenu()`),
applied additively on top of every wing's own existing constants, visible immediately on real
hardware (no rebuild between nudges — same live-@AppStorage mechanism the existing production
"Island Size" Width/Depth sliders already use), and exported via a "Print Wing Tuner Values"
menu action that dumps the 4 current deltas to the Xcode console in copy-paste form.

Every wing keeps its own existing constants (`margin`, `leadingPad`/`iconLeadingPad`,
`trailingPad`, inner icon/text `HStack(spacing:)`/`iconLabelGap`) untouched at rest (all 4
nudges default to 0 -> zero visual change until the user opens the debug menu). Two known-unsafe
spots (Meeting wing's `margin` and `iconGap`, both load-bearing for a click-through-zone
assert/invariant) are deliberately excluded from those 2 axes there — documented in Task 2.

Purpose: replace slow on-device guess-rebuild-report cycles for wing icon/text clipping and
alignment with a single-session "nudge live, note the printed delta, paste it to Claude" loop.
Output: `Islet/ActivitySettings.swift` (4 new DEBUG-only key constants), `Islet/Notch/NotchPillView.swift`
(4 DEBUG-only `@AppStorage`-backed nudge properties + wiring into all 13 wing-content functions),
`Islet/AppDelegate.swift` (a "Wing Tuner" debug submenu: 8 nudge actions + Reset + Print).
Zero effect on Release builds (`#if DEBUG` throughout, matching this codebase's own
`setupDebugMenu()`/`islandWidthScaleOffset` conventions).
</objective>
