**Task 1 — `focusWings(for:)` today (`Islet/Notch/NotchPillView.swift` ~3340-3370), no margin:**
```swift
private func focusWings(for activity: FocusActivity) -> some View {
    let widthGrowth = max(1.0, resolvedWingWidthScale)
    return wingsShape(
        leftWidth: 118 * widthGrowth,
        rightWidth: 160 * widthGrowth,
        depthScale: resolvedWingDepthScale
    ) {
        HStack(spacing: 0) {
            Image(systemName: "moon.fill")
                .font(.system(size: 13, weight: .semibold))
                .symbolRenderingMode(.hierarchical)
                .foregroundStyle(.white)
                .padding(.leading, 14 + wingLeadingNudge)
            Spacer()                                      // clears the physical camera bridge
            HStack(spacing: 4 + wingGapNudge) {
                Circle().fill(Color.green)
                Text("On")
                    .font(.system(size: 12, weight: .semibold, design: .rounded))
                    .foregroundStyle(.white)
            }
            .padding(.trailing, 20 + wingTrailingNudge)
        }
    }
}
```
Its own header comment documents `leftWidth: 118` as already sitting near the bare
camera-clearance floor ("Floor is the physical notch half-width (~89.5pt) + icon + its leading
padding — going below that renders the icon under the camera housing... which is what
`leftWidth: 100` did"), meaning there is very little slack on the left side specifically — do
not derive a big notch-cutout-relative `margin` here (that would require deriving
`leftWidth`/`rightWidth` FROM `margin`, the way `osdWings`/`capsLockWings`/`updateWings` do,
which would substantially widen this wing from its current small 118/160 footprint — out of
scope and a real visual regression). Instead, replace the un-nudgeable `Spacer()` with an
explicit fixed-width element so `wingMarginNudge` has a real, visible, bidirectional effect
while `leftWidth`/`rightWidth` (and therefore this wing's total on-screen footprint) stay
byte-for-byte unchanged.
